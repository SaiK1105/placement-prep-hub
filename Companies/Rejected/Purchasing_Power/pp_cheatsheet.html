Python idioms

Explicitly reported as MCQ content: lambda, list comprehensions, dictionary questions. These are the cheapest marks on the paper.

[x*2 for x in a if x > 0]      # list comp: expression, loop, condition — in that order
{k: v for k, v in d.items()}   # dict comprehension
lambda x: x + 1                # anonymous, single expression, no return keyword

d.get(k, default)              # never raises
d[k]                           # raises KeyError if missing
d.items() / d.keys() / d.values()

a[::-1]                        # reverse
a[1:4]                         # indices 1,2,3 — stop is EXCLUDED
a[-1]                          # last element

sorted(a, key=lambda x: x[1])  # returns a NEW list
a.sort()                       # in-place, returns None

Traps

  • a.sort() returns None — b = a.sort() makes b None. sorted() returns the list.
  • Mutable default argument — def f(x, lst=[]) keeps the same list across calls. It is created once at definition, not per call.
  • is compares identity, == compares value.
  • Slicing never raises on out-of-range; indexing does.
  • range(a, b) excludes b. len() is a function, not a method.
  • Integer division is //; / always yields a float in Python 3.

SQL

Highest-yield topic on the paper. SQL appears in the MCQ section, the coding section, and both interview rounds. 
INNER JOIN   → only rows matching in BOTH tables
LEFT JOIN    → all left rows + matched right (NULL where unmatched)
RIGHT JOIN   → mirror of LEFT
FULL OUTER   → everything from both sides
CROSS JOIN   → cartesian product
SELF JOIN    → table joined to itself (needs aliases)

Execution order — not the written order

FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY → LIMIT

This is why you cannot use a SELECT alias in WHERE (it doesn't exist yet), but you can in ORDER BY.

The facts that get asked

  • COUNT(*) counts all rows including NULLs. COUNT(col) SKIPS NULLs. Most-asked SQL MCQ.
  • WHERE filters rows before grouping. HAVING filters groups after.
  • NULL: use IS NULL / IS NOT NULL. NULL = NULL is never TRUE.
  • Aggregates (SUM, AVG, MAX) ignore NULL. Any arithmetic with NULL yields NULL.
  • UNION removes duplicates; UNION ALL keeps them (and is faster).
  • DISTINCT applies to the whole select list, not one column.
  • DELETE (DML, rollback-able, takes WHERE) vs TRUNCATE (DDL, no WHERE) vs DROP (removes the table).
  • Every non-aggregated SELECT column must appear in GROUP BY.
SELECT dept, COUNT(*) AS n, AVG(salary) AS avg_sal
FROM employees
WHERE active = 1            -- filters ROWS first
GROUP BY dept
HAVING COUNT(*) > 5         -- filters GROUPS after
ORDER BY avg_sal DESC
LIMIT 10;

Box plot — know the five numbers

  |------[ ###|##### ]------|      o    o
 min     Q1  med   Q3      max   outliers
          |--- IQR box ---|
  • Line inside the box is the MEDIAN, not the mean.
  • Box spans Q1 → Q3. IQR = Q3 − Q1. Whiskers reach 1.5 × IQR; beyond that = outliers.
  • Shows median, quartiles, spread, skew, outliers. Does not show the mean, sample size, or distribution shape — a histogram does that.
  • Median closer to Q1 → right-skewed (long right tail).

Distinctions that get tested

  • Histogram vs bar chart: histogram bars touch (continuous, binned numeric); bar chart bars have gaps (discrete categories). Most-asked pair.
  • Scatter shows correlation, not causation. Any option claiming proof of cause is wrong.
  • Truncated y-axis (not starting at 0) exaggerates differences — the standard "which chart misleads?" answer.
  • Pie fails beyond ~6 slices and cannot show change over time.
  • Stacked bar segments are hard to compare because they don't share a baseline.

Stats & data interpretation

Central tendency

  • Mean is pulled by outliers; median is not. Skewed data (income, house prices) → report the median.
  • Right-skewed: mean > median. Left-skewed: mean < median. Symmetric: mean = median = mode.
  • Range = max − min. Variance = avg squared deviation. SD = √variance, in the original units.

Hypothesis testing

  • H₀ = null (no effect / no difference). H₁ = alternative.
  • p-value = probability of seeing data this extreme if H₀ were true. p < α (usually 0.05) → reject H₀.
  • You never "accept" H₀ — you fail to reject it.
  • Type I error = rejecting a true H₀ (false positive, rate α). Type II = failing to reject a false H₀ (false negative, β). Power = 1 − β.
  • t-test compares means · chi-square tests categorical association · ANOVA compares 3+ group means.

Correlation

  • r ranges −1 to +1. 0 = no linear relationship (a curved relationship can still exist).
  • |r| near 1 = strong. Sign = direction.

Data sufficiency technique

Don't solve — decide only whether it's solvable. Check statement 1 alone, then statement 2 alone, then both together, in that order. Never let information from statement 1 leak into your evaluation of statement 2.

Coding

The reported question — run-length decode

def decode(s):                        # "a3b2" -> "aaabb"
    return "".join(s[i] * int(s[i+1]) for i in range(0, len(s), 2))

# longhand, if you want it explicit:
def decode(s):
    out = []
    for i in range(0, len(s), 2):
        out.append(s[i] * int(s[i+1]))
    return "".join(out)

The encode direction, in case they flip it

def encode(s):                        # "aaabb" -> "a3b2"
    out, i = [], 0
    while i < len(s):
        j = i
        while j < len(s) and s[j] == s[i]:
            j += 1
        out.append(s[i] + str(j - i))
        i = j
    return "".join(out)

Aptitude — 15 questions, easy tier

  • Speed/distance: average speed over equal distances = harmonic mean 2xy/(x+y), never the plain average.
  • Time & work: take total work = LCM of the given days. Work in whole units, never fractions.
  • Percentages: successive x% then y% = x + y + xy/100. An increase then an equal decrease always gives a net loss.
  • Profit/loss: always calculated on cost price unless stated otherwise.
  • Ratio: convert to a common multiplier k and solve for k.
  • P&C: arrangement → permutation; selection → combination. nCr = nC(n−r).
  • Probability: favourable/total. "At least one" → 1 − P(none).
  • Venn: n(A∪B) = n(A) + n(B) − n(A∩B).
  • Averages: if the average changes by d when one value is replaced, the difference between the values is n × d.
Technique over formula. Eliminate using the options and unit digits before computing anything fully. On an easy-tier section, the arithmetic is not the bottleneck — the clock is.
