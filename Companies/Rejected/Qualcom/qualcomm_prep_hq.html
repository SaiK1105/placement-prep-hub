🔧 C/C++ Output Prediction

The hardest section, and your biggest gap as a Python-primary candidate. Good news: you're reading code here, not authoring it — tracing is a skill you already have. Work through these, reveal only after committing to an answer out loud.

Q1 · STORAGE CLASSES
void f() { static int x = 0; x++; printf("%d ", x); }
int main() { f(); f(); f(); return 0; }
1 2 3
static inside a function: initialised ONCE, persists across calls, retains value. Without static it would print 1 1 1. This is the single most-tested storage-class fact.
Q2 · SIZEOF
char str[] = "hello";
printf("%lu", sizeof(str));
6 — 5 characters + the '\0' null terminator. Contrast strlen(str) which is 5 (stops at the null). sizeof-vs-strlen is a classic trap pair.
Q3 · ARRAY DECAY gotcha
void f(int arr[]) { printf("%lu", sizeof(arr)); }
int main() { int a[10]; f(a); }
8 (pointer size on 64-bit; 4 on 32-bit) — not 40. An array parameter decays to a pointer; the function has no idea of the original size. Inside main, sizeof(a) WOULD be 40. This is why C functions always take a length parameter.
Q4 · POINTER ARITHMETIC
int arr[] = {10,20,30,40,50};
int *p = arr;
printf("%d %d", *(p+2), *(arr+4));
30 50 — p+2 advances by 2×sizeof(int), not 2 bytes. Pointer arithmetic scales by the pointed-to type. And arr[i] is literally defined as *(arr+i).
Q5 · THE COMMUTATIVE INDEX TRICK
int a[] = {1,2,3};
printf("%d", 2[a]);
3 — since a[2] means *(a+2), and addition commutes, 2[a] means *(2+a) — identical. Legal C, and a favourite "is this even valid?" MCQ.
Q6 · PRE / POST INCREMENT
int i = 5;
int j = i++;
int k = ++i;
printf("%d %d %d", i, j, k);
7 5 7 — i++ returns the OLD value (5) then increments i to 6. ++i increments first (to 7) then returns 7. Final i = 7.
Q7 · SHORT-CIRCUIT EVALUATION
int i = 0;
if (i++ && i++) { }
printf("%d", i);
1 — the first i++ evaluates to 0 (falsy), so && short-circuits and the second i++ never runs. i incremented exactly once. Same idea with || when the left side is true.
Q8 · INTEGER DIVISION + PRECEDENCE
printf("%d %d", 7/2*2, 2+3*4);
6 14 — 7/2 is integer division = 3 (truncates, doesn't round), then ×2 = 6. * binds tighter than +, so 2+12 = 14. Integer truncation is the most common silent-wrong-answer source.
Q9 · UNSIGNED LOOP infinite-loop trap
for (unsigned int i = 5; i >= 0; i--) printf("%u ", i);
Infinite loop. An unsigned can never be < 0. When i is 0 and decrements, it wraps around to 4294967295. The condition i >= 0 is always true. Answer options usually include "5 4 3 2 1 0" as the trap.
Q10 · CHAR ARITHMETIC
char c = 'A';
printf("%c %d", c + 2, c);
C 65 — chars are small integers. 'A' is ASCII 65, +2 = 67 = 'C'. The format specifier decides how it's displayed. Remember: 'A'=65, 'a'=97, '0'=48.
Q11 · BITWISE OPERATORS
printf("%d %d %d %d %d", 5&3, 5|3, 5^3, 5<<1, 5>>1);
1 7 6 10 2 — 5=101, 3=011. AND=001=1 · OR=111=7 · XOR=110=6 · left-shift doubles (10) · right-shift halves, truncating (2). Left-shift by n = ×2ⁿ; right-shift by n = ÷2ⁿ.
Q12 · NUMBER BASES
printf("%d %d %d", 0x1A, 017, 0xFF);
26 15 255 — 0x prefix = hex (1A = 16+10 = 26). A leading zero alone means OCTAL, so 017 = 8+7 = 15, not 17. That octal trap appears constantly.
Q13 · POINTER TO POINTER
int x = 10; int *p = &x; int **pp = &p;
printf("%d %d", **pp, *p);
10 10 — pp holds the address of p, which holds the address of x. Each * dereferences one level. Count the stars: two stars = two hops to the value.
Q14 · CONST POINTER vs POINTER TO CONST
const int *p;     // A
int * const q;    // B
A = pointer to a const int — you CAN change what p points to, you CANNOT change *p.
B = const pointer to int — you CANNOT change q itself, you CAN change *q.
Read right-to-left from the variable name. "const int *" → const applies to the int; "* const" → const applies to the pointer.
Q15 · C++ CONSTRUCTOR / DESTRUCTOR ORDER
class A { public: A(){cout<<"A";} ~A(){cout<<"~A";} };
class B : public A { public: B(){cout<<"B";} ~B(){cout<<"~B";} };
int main() { B b; }
AB~B~A — construction goes BASE → DERIVED (build the foundation first); destruction is exactly reversed, DERIVED → BASE. Mnemonic: last built, first destroyed — a stack.
Q16 · VIRTUAL FUNCTIONS high-frequency
class Base    { public: virtual void show(){cout<<"Base";} };
class Derived : public Base { public: void show(){cout<<"Derived";} };
int main() { Base *b = new Derived(); b->show(); }
Derived — with virtual, the call resolves at RUNTIME by the actual object type (dynamic dispatch). Remove virtual and it prints "Base" — resolved at compile time by the pointer type. The whole question hinges on that one keyword; check for it first.
Q17 · ARRAY SIZE IDIOM
int arr[5];
printf("%lu", sizeof(arr)/sizeof(arr[0]));
5 — total bytes (20) ÷ bytes per element (4). The standard C idiom for array length. Note it only works where the array hasn't decayed to a pointer (see Q3).
Q18 · STRING vs CHAR ARRAY
char s[] = "Hi";
char *p  = "Hi";
// which one can legally do s[0]='h' / p[0]='h'?
s[0]='h' is fine; p[0]='h' is undefined behaviour (typically a segfault). s is a modifiable copy on the stack; p points into a read-only string literal. Modifying a string literal is the classic crash MCQ.
Q19 · STATIC AT FILE SCOPE
// file1.c
static int counter = 0;
Internal linkage — the variable is visible only within this translation unit; another file cannot reach it with extern. So static means two different things: inside a function = persists across calls (Q1); at file scope = hides from other files. Both get tested.
Q20 · POST-INCREMENT ON A POINTER
int a[] = {1,2,3}; int *p = a;
printf("%d ", *p++);
printf("%d", *p);
1 2 — *p++ parses as *(p++): post-increment returns the OLD pointer, dereferenced → 1; p then points at element 2. Compare (*p)++ which would leave p alone and change the array value to 2.

⚡ If you only memorise five things

  • static in a function persists; at file scope it hides.
  • sizeof(array) = total bytes, but an array parameter has already decayed to a pointer.
  • Integer division truncates: 7/2 = 3. Leading zero = octal: 017 = 15.
  • virtual → runtime dispatch (Derived); no virtual → compile-time (Base).
  • Construction base→derived, destruction derived→base.

🧠 CS Core — Section 3 (take Computer Science)

Theory, not coding. Skim these; they're the highest-density facts that appear in campus MCQs.

Operating Systems

  • Process vs Thread: processes have separate address spaces; threads share code/data/heap but have their own stack + registers. Thread switching is cheaper.
  • Scheduling: FCFS (convoy effect) · SJF (optimal average wait, needs burst prediction) · Round Robin (time quantum; small quantum = more context-switch overhead) · Priority (starvation → fix with aging).
  • Deadlock — 4 necessary conditions: mutual exclusion, hold-and-wait, no preemption, circular wait. Break any one to prevent. Banker's algorithm = avoidance.
  • Paging vs Segmentation: paging = fixed-size blocks, causes internal fragmentation; segmentation = variable-size logical units, causes external fragmentation.
  • Page replacement: FIFO (suffers Belady's anomaly) · LRU · Optimal (theoretical benchmark).
  • Semaphore vs Mutex: mutex = binary lock with ownership (only the locker unlocks); semaphore = counter, no ownership, can signal across threads.
  • Thrashing: excessive paging because working set > available frames.

DBMS / RDBMS

  • ACID: Atomicity (all-or-nothing) · Consistency (valid state→valid state) · Isolation (concurrent txns don't interfere) · Durability (committed survives crash).
  • Normal forms: 1NF = atomic values, no repeating groups · 2NF = 1NF + no partial dependency on part of a composite key · 3NF = 2NF + no transitive dependency · BCNF = stricter 3NF (every determinant is a candidate key).
  • Keys: super key ⊇ candidate key → one chosen as primary key (unique + NOT NULL, one per table). Foreign key references another table's PK. UNIQUE allows NULLs; PK doesn't.
  • Joins: INNER (matches only) · LEFT (all left rows, NULLs on no match) · RIGHT · FULL OUTER · CROSS (cartesian product).
  • Indexing: speeds SELECT, slows INSERT/UPDATE/DELETE. Clustered = physical row order (one per table); non-clustered = separate structure with pointers. Usually B+ trees.
  • NULL: nothing ever = NULL — comparisons yield unknown. Use IS NULL. COUNT(*) counts rows including NULLs; COUNT(col) skips NULLs.
  • WHERE vs HAVING: WHERE filters rows before grouping; HAVING filters groups after aggregation.

Computer Networks

  • OSI 7 layers: Physical · Data Link · Network · Transport · Session · Presentation · Application. ("Please Do Not Throw Sausage Pizza Away.") TCP/IP model collapses these into 4.
  • TCP vs UDP: TCP = connection-oriented, reliable, ordered, 3-way handshake (SYN → SYN-ACK → ACK), flow + congestion control, 20-byte header. UDP = connectionless, unreliable, fast, 8-byte header (DNS, video, VoIP).
  • Layer→device: hub = physical · switch = data link (MAC) · router = network (IP).
  • Ports: HTTP 80 · HTTPS 443 · FTP 20/21 · SSH 22 · Telnet 23 · SMTP 25 · DNS 53.
  • IP classes: A 1–126 · B 128–191 · C 192–223. Private ranges: 10.x, 172.16–31.x, 192.168.x. Loopback 127.0.0.1.
  • ARP maps IP→MAC. DNS maps name→IP. DHCP assigns IPs dynamically.

Data structures — theory, not implementation

  • Complexities: array access O(1)/search O(n) · linked list access O(n)/insert-at-head O(1) · hash table avg O(1), worst O(n) · BST balanced O(log n), degenerate O(n) · heap insert/extract O(log n), peek O(1).
  • Sorting: quicksort avg O(n log n), worst O(n²) (already-sorted with bad pivot), in-place, not stable · mergesort always O(n log n), O(n) space, stable · heapsort O(n log n), in-place, not stable · bubble/insertion/selection O(n²) — insertion is O(n) on nearly-sorted data.
  • Stack = LIFO (function calls, undo, DFS) · Queue = FIFO (BFS, scheduling).
  • Traversals: inorder on a BST yields sorted order. Preorder = root-left-right (copying a tree), postorder = left-right-root (deleting a tree).
  • BFS uses a queue, finds shortest path in an unweighted graph. DFS uses a stack/recursion, used for cycle detection and topological sort.

🧮 Aptitude — Section 1

Easy–medium and a full third of the paper. Speed matters more than cleverness: 30 min for 20 questions = 90 seconds each.

Formula sheet

  • Speed/Time/Distance: D = S×T. Average speed for equal distances = 2xy/(x+y), not (x+y)/2. Relative speed: same direction = |a−b|, opposite = a+b. Train passing a pole: length/speed; passing a platform: (length+platform)/speed.
  • Time & Work: if A takes x days, A's rate = 1/x per day. Together: 1/x + 1/y. Work done = rate × time. M₁D₁H₁/W₁ = M₂D₂H₂/W₂.
  • Percentages: increase then decrease by same r% → net change = −r²/100 (always a loss). Successive changes a% then b% → a + b + ab/100.
  • Profit/Loss: P% = (SP−CP)/CP × 100. Two items sold at same price, one at +r% one at −r% → always a net LOSS of r²/100 %.
  • Ratio/Proportion: if a:b = c:d then ad = bc. Divide N in ratio a:b → parts are Na/(a+b), Nb/(a+b).
  • Mixtures/Alligation: (cheaper qty)/(dearer qty) = (dearer price − mean)/(mean − cheaper price). Repeated replacement: final = initial × (1 − r/V)ⁿ.
  • P & C: nPr = n!/(n−r)! (order matters) · nCr = n!/(r!(n−r)!) (order doesn't). Circular arrangements of n = (n−1)!. At least one = total − none.
  • Probability: P = favourable/total. P(A or B) = P(A)+P(B)−P(A and B). Independent: P(A and B) = P(A)×P(B). P(not A) = 1 − P(A).
  • Number systems: divisibility — 3 (digit sum), 4 (last two digits), 8 (last three), 9 (digit sum), 11 (alternating sum). LCM×HCF = product of the two numbers.
  • SI/CI: SI = PRT/100. CI amount = P(1+R/100)ᵀ. Difference for 2 years = P(R/100)².

Speed tactics

  • Check the options first. Many MCQs are faster solved by substituting options than by solving forward.
  • Approximate aggressively when options are far apart — exact arithmetic is wasted effort.
  • Percentage↔fraction: 12.5%=1/8 · 16.67%=1/6 · 25%=1/4 · 33.33%=1/3 · 37.5%=3/8 · 66.67%=2/3 · 75%=3/4. Converting to fractions kills most percentage arithmetic instantly.
  • DI sets: read the question before the chart — you usually need two numbers, not the whole table.
  • Skip the paragraph-heavy logical puzzle if it's over 90 seconds. One puzzle can eat five easy marks' worth of time.
