Section 2 — the 10 traps

Before answering any C/C++ question, identify which of these it is. If it doesn't feel like one of them, re-read — you've probably misidentified it.

  1. Integer division truncates. 7/2=3, -7/2=-3. Never rounds. 7/2*2=6.
  2. sizeof vs strlen, and array decay. char s[]="hello" → sizeof 6, strlen 5. An array passed to a function decays to a pointer → sizeof inside = 8.
  3. Pre vs post increment. i++ yields the OLD value then increments; ++i increments then yields the NEW. Both leave i incremented.
  4. Short-circuit. && stops at the first false, || at the first true — side effects on the skipped side never happen.
  5. Leading zero = OCTAL. 017 = 15, not 17. 0x1A = 26.
  6. Unsigned is never < 0. for(unsigned i=5; i>=0; i--) is an infinite loop — 0 wraps to 4294967295.
  7. static persists. A local static initialises once, keeps its value across calls, defaults to 0. Prints 1 2 3, not 1 1 1.
  8. Precedence. a & 1 == 0 parses as a & (1==0) — bitwise binds looser than ==. *p++ is *(p++).
  9. Ctor / dtor order. Construction base→derived, destruction derived→base. B b; → A B ~B ~A.
  10. virtual present or absent. Base* b = new Derived(); b->show(); — with virtual calls Derived, without calls Base. That one keyword IS the question.
Method: build a two-column trace table — variable | value after each line. The answer falls out. Guessing from "reading the code" is where the −0.25 comes from. 90 s per question is generous for tracing; your risk is panic-skipping, not the clock.

Other operators

  • Ternary nests right-to-left: a?b:c?d:e is a?b:(c?d:e).
  • Comma operator (1,2,3) evaluates all, yields the last → 3. Different from an initialiser {1,2,3}.
  • Number literals: 0x1A hex = 26 · 017 octal = 15 · 17 decimal.

Control flow

  • do…while runs the body at least once, checks after.
  • while(i++ < 3) compares the old i, then increments. Off-by-one traps live here.
  • switch falls through without break — count labels until the next break.
  • 0 is false; every non-zero is true, including negatives.
  • if (x = 5) assigns and yields 5 → always true. Classic spot-the-bug answer.
  • No elif — it's else if.

Arrays & strings

  • Zero-indexed, no bounds checking, no negative indexing. a[-1] is garbage, not the last element.
  • Partial init zero-fills: int a[5]={1,2} → {1,2,0,0,0}.
  • a[i] is defined as *(a+i) — so 2[a] is legal C and equals a[2].
  • Size idiom sizeof(arr)/sizeof(arr[0]) — works only in the declaring scope.
  • char s[]="hello" → sizeof 6 (5 + '\0'), strlen 5.
  • char *s="abc" is a read-only literal; char s[]="abc" is a modifiable copy.
  • 2D int a[3][4]: sizeof(a)=48 · sizeof(a[0])=16 (one row) · sizeof(a[0][0])=4.

Pointers

int x = 10;
int *p = &x;     // p holds the ADDRESS of x
*p               // 10  — "the value at"
&x               // the address of x
int **pp = &p;   // *pp is p, **pp is 10   — count the stars
  • * in a declaration = "is a pointer"; in an expression = "value at".
  • Pointer arithmetic scales by the pointed-to type. p+2 on an int* advances 8 bytes, not 2.
  • Array decay: passing an array to a function passes only a pointer — the function cannot know the length. That's why C functions always take a separate size parameter.
  • const, read right-to-left from the name:
    const int *p → pointer to const int: can repoint p, cannot change *p.
    int * const q → const pointer: cannot repoint q, can change *q.
  • C passes everything by value. swap(int a, int b) does nothing to the caller — it needs pointers.

Structs & unions

struct S { char c; int i; char d; };
// 1 + 3 pad + 4 + 1 + 3 pad = 12   (NOT 6)
  • Access: s.field for a value, p->field for a pointer (p->i ≡ (*p).i).
  • Padding: members align to their own size; total rounds up to a multiple of the largest member's alignment. Reordering members changes sizeof — a favourite question.
  • union: all members share the same memory. sizeof = largest member. Writing one clobbers the others.

C++ / OOPS

  • Ctor/dtor order: construction base → derived; destruction exactly reversed, derived → base. Mnemonic: last built, first destroyed — a stack. class B : public A, B b; → A B ~B ~A.
  • Members are constructed in declaration order, not initialiser-list order.
  • virtual = runtime dispatch. Base *b = new Derived(); b->show(); → with virtual calls Derived's (decided by the object); without, calls Base's (decided by the pointer type).
  • Virtual destructor: delete base_ptr on a derived object runs only ~Base unless the base destructor is virtual. Hence: any class meant to be inherited from gets a virtual destructor.
  • Overloading = same name, different parameters, resolved at compile time. Overriding = derived redefines a virtual, resolved at runtime.
  • Access: private (class only) · protected (class + derived) · public. Default: class → private, struct → public.
  • Pure virtual virtual void f() = 0; → abstract class → cannot be instantiated.
  • Four pillars: encapsulation, abstraction, inheritance, polymorphism (compile-time = overloading, runtime = overriding).

Section 3 — Operating Systems

  • Process = program in execution with its own memory. Thread shares the process's memory.
  • States: new → ready → running → waiting → terminated.
  • Scheduling: FCFS (convoy effect) · SJF (optimal average wait, needs burst times) · Round Robin (time quantum, fair) · Priority (starvation → fixed by ageing).
  • Deadlock — 4 necessary conditions: mutual exclusion, hold-and-wait, no preemption, circular wait. Break any one to prevent. Banker's algorithm = avoidance.
  • Paging = fixed-size pages → internal fragmentation. Segmentation = variable size → external fragmentation.
  • Page replacement: FIFO (suffers Belady's anomaly), LRU, Optimal. Thrashing = excessive page faults, near-zero throughput.
  • Semaphore (counting or binary, any process can signal) vs mutex (ownership — only the locker unlocks).
  • Deadlock (circular wait) vs starvation (indefinitely postponed) vs race condition (order-dependent result).

Section 3 — DBMS

  • Normal forms: 1NF atomic values · 2NF no partial dependency on part of a composite key · 3NF no transitive dependency · BCNF every determinant is a candidate key.
  • Keys: super → candidate → primary. Foreign key references another table's primary key.
  • ACID: Atomicity, Consistency, Isolation, Durability.
  • Isolation levels: Read Uncommitted (dirty read) → Read Committed → Repeatable Read (phantom reads) → Serializable.
  • Indexes speed reads, slow writes. Clustered index = physical row order, one per table.
  • DELETE (DML, rollback-able, takes WHERE) vs TRUNCATE (DDL, no WHERE, resets) vs DROP (removes the structure).
  • COUNT(*) counts all rows; COUNT(col) skips NULLs. WHERE filters rows before grouping, HAVING filters groups after.

Section 3 — Computer Networks

  • OSI 7 layers: Physical, Data Link, Network, Transport, Session, Presentation, Application. (Please Do Not Throw Sausage Pizza Away)
  • TCP: connection-oriented, reliable, ordered, 3-way handshake (SYN → SYN-ACK → ACK), slower. UDP: connectionless, no delivery guarantee, fast — streaming, DNS, VoIP.
  • Devices by layer: hub = L1 · switch = L2 · router = L3.
  • IPv4 = 32-bit, IPv6 = 128-bit. Private ranges: 10.x · 172.16–31.x · 192.168.x.
  • Ports: HTTP 80 · HTTPS 443 · FTP 20/21 · SSH 22 · Telnet 23 · SMTP 25 · DNS 53.
  • DNS = name → IP · DHCP = assigns IPs · ARP = IP → MAC · NAT = private ↔ public.
  • Routing: distance vector (RIP, Bellman-Ford, hop count) vs link state (OSPF, Dijkstra).

Section 3 — Data structures (theory)

  • Stack LIFO — function calls, undo, DFS, expression evaluation. Queue FIFO — BFS, scheduling.
  • Array: O(1) access, O(n) insert/delete. Linked list: O(n) access, O(1) insert at a known node.
  • BST: search/insert average O(log n), worst O(n) when skewed. Balanced variants: AVL, Red-Black.
  • Traversals: inorder (L, root, R) → sorted order for a BST · preorder (root, L, R) · postorder (L, R, root) · level-order uses a queue.
  • Hash table: average O(1); collisions handled by chaining or open addressing.
  • Heap = complete binary tree. Min-heap root is smallest. Build O(n), insert/delete O(log n).
  • Sorting: bubble/insertion/selection O(n²) · merge O(n log n) stable, O(n) extra space · quick O(n log n) average but O(n²) worst · heap O(n log n) in-place.
  • Graphs: BFS uses a queue (shortest path in unweighted), DFS uses a stack/recursion. Dijkstra = weighted shortest path, no negative edges.

Section 1 — Aptitude & logical

  • Speed/distance: average speed over equal distances = 2xy/(x+y), never the plain average.
  • Time & work: set total work = LCM of the given days, then work in whole units.
  • Percentages: successive x% then y% = x + y + xy/100. Increase then equal decrease → net loss.
  • Profit/loss: always on cost price unless stated.
  • Ratio: convert to a common multiplier k, solve for k.
  • P&C: arrangement → permutation, selection → combination. nCr = nC(n−r).
  • Probability: favourable/total. "At least one" → 1 − P(none).
  • Venn: n(A∪B) = n(A) + n(B) − n(A∩B).
  • Number systems: divisibility rules; unit-digit cycles have length 4 for 2, 3, 7, 8.
  • Mixtures: alligation — the ratio of quantities is the inverse ratio of the distances from the mean.
