04DSA & Python fundamentals

The JD says "strong fundamentals in data structures" and "comfortable programming in Python" — read literally, not "DSA grind." Expect these to surface as live-coding or rapid-fire conceptual questions, not LeetCode Hard.

Arrays vs. linked lists

O(1) random access vs O(1) insert/delete at a known node. Know when Python's list (dynamic array) beats a manual linked structure — almost always, unless you need O(1) mid-sequence insert/delete at scale.

Hash maps

dict in Python — average O(1) lookup/insert, O(n) worst case on pathological collisions. This is your single highest-yield tool for turning O(n²) brute force into O(n).

Two pointers / sliding window

For any "contiguous subarray/substring satisfying X" problem — converts an O(n²) nested loop into O(n) by moving one boundary instead of restarting.

Recursion & stack depth

Every recursive call is a stack frame. Know the base case first, always. Python's default recursion limit (~1000) matters if you reach for recursion under pressure — mention iterative fallback if asked.

Time/space complexity

Be able to state Big-O for anything you write, unprompted. Nested loop over n → O(n²). Single hash-map pass → O(n) time, O(n) space. This is table-stakes, not a bonus.

Python idioms

List/dict comprehensions, enumerate, zip, unpacking, collections.Counter/defaultdict. Writing idiomatic Python under pressure signals "comfortable," not just "can write Python."

Mutable default args

Classic Python gotcha: def f(x, cache=[]) shares one list across all calls. Know it, because it's cheap interview ammunition for "have you actually used Python."

OOP basics

Class vs instance attributes, __init__, inheritance, when composition beats inheritance. Your resume claims OOAD — be ready to justify a design choice, not just define terms.

Drill

ComplexityWhat's the time complexity of checking whether two strings are anagrams using a Counter comparison?
O(n)Building each Counter is O(n); comparing two Counters is O(k) where k is alphabet size (constant for fixed charset). Sorting both strings instead would be O(n log n) — worse, and a common "correct but suboptimal" answer.
Data structuresYou need O(1) average lookup, insertion, and deletion, and don't care about order. Which Python structure?
set (or dict if you need associated values)A list gives O(n) lookup/delete. A set is a hash table — the right default whenever membership testing dominates.
Python gotchaWhy is def append_to(item, target=[]): dangerous?
Default mutable arguments are evaluated once, at function definition timeEvery call that doesn't pass target explicitly shares and mutates the same list object across calls. Fix: default to None, then target = target or [] inside the body.
RecursionWhat's the space complexity of a naive recursive Fibonacci(n) call, and why does it matter separately from time?
O(n) space (call stack depth), O(2ⁿ) timeSpace is bounded by the deepest single branch of the recursion tree, not the total number of calls. This is why "it's exponential" alone is an incomplete answer — interviewers listen for whether you separate the two axes.
OOPWhen would you prefer composition over inheritance?
When the relationship is "has-a" not "is-a," or when you need to swap behavior at runtimeInheritance locks in a hierarchy at design time and leaks parent implementation details. Composition (e.g. a class holding a strategy object) is more flexible and is the default in most modern Python/backend design — good to say explicitly given the JD's OOAD mention.
Sliding windowGiven an array, find the length of the longest subarray with sum ≤ K. What's the pattern and complexity?
Variable-size sliding window, O(n) time, O(1) spaceExpand the right boundary, and while the running sum exceeds K, shrink from the left. Each index enters and leaves the window at most once, so total work is O(n) despite looking nested.

05DBMS / SQL fundamentals

JD says "databases" explicitly. Given the product is document-heavy insurance data on Azure, expect both relational (structured policy/claims records) and possibly NoSQL/vector reasoning (your RAG background covers the latter already).

Normalization

1NF/2NF/3NF in one sentence each: no repeating groups → no partial dependency on a composite key → no transitive dependency on non-key columns. Know why you'd denormalize anyway (read-heavy analytics, avoiding join cost).

Joins

INNER vs LEFT/RIGHT vs FULL OUTER. Be able to write one from memory involving a claims/policy-style two-table schema — this is the most likely live-SQL ask.

Indexes

Speed up reads, cost writes and storage. B-tree default; know that indexing every column isn't "faster," it's a trade-off you should be able to articulate.

Transactions & ACID

Atomicity, Consistency, Isolation, Durability. For an insurance platform processing claims, this is a natural "why does this matter here" follow-up — a half-committed claim update is a real business problem, not a textbook abstraction.

SQL vs NoSQL vs vector DB

You already know this cold from LanceDB/Redis work — be ready to generalize it: structured transactional data → relational; flexible/nested docs → NoSQL; semantic similarity search → vector DB. Map it explicitly to "insurance documents" if asked.

Drill

SQLWrite a query returning each policyholder's name and their total claim amount, including policyholders with zero claims.
SELECT p.name, COALESCE(SUM(c.amount), 0) AS total_claims
FROM policyholders p
LEFT JOIN claims c ON c.policyholder_id = p.id
GROUP BY p.name;
LEFT JOIN keeps policyholders with no matching claims rows; COALESCE turns the resulting NULL sum into 0. INNER JOIN here would silently drop zero-claim customers — a real correctness bug in an insurance context.
IndexingYou index a column that's updated on almost every write. What's the trade-off?
Faster reads on that column, slower writesEvery INSERT/UPDATE now also has to update the index structure. On a write-heavy table, an unnecessary index can dominate write latency — the right answer is "it depends on read:write ratio," not "always index."
ACIDWhy does isolation matter for a claims-processing system specifically?
Prevents two concurrent claim updates from reading stale intermediate stateE.g. two adjusters processing the same claim simultaneously — without proper isolation you can get lost updates or dirty reads, which in an insurance payout context is a direct financial/compliance risk, not just a bug.
Data modelingWould you store unstructured insurance PDFs (policy docs) in the relational DB directly?
No — store the file in blob/object storage (e.g. Azure Blob), keep a reference/metadata row in the relational DB, and index extracted text/embeddings in a vector storeThis is exactly the architecture your RLM and A.R.G.U.S-V projects already implement — say so. It shows you're not reciting theory, you've built this pattern.

06LLM / RAG / Agentic AI — your strongest section

The JD asks for a "working understanding" — your resume shows you've actually built this, three times over. The risk here isn't knowledge, it's articulating it crisply under pressure instead of rambling through a project. Practice saying these out loud, not just reading them.

How an LLM generates text

Autoregressive next-token prediction over a learned probability distribution, conditioned on all prior tokens (context window). Temperature/top-p control sampling randomness. Be ready for "what is a token" and "what is the context window" as bare-bones checks.

RAG, precisely

Retrieve relevant chunks (via embedding similarity search over a vector store) → inject them into the prompt as context → generate grounded on that context instead of parametric memory alone. Core benefit: reduces hallucination, adds fresh/private knowledge without retraining.

Embeddings & semantic search

Text → dense vector such that semantically similar text lands close in vector space (cosine/dot-product similarity). This is what LanceDB/Redis-as-vector-store are doing in your projects.

Agentic AI

An LLM that doesn't just respond once, but plans, calls tools/functions, observes results, and iterates — vs. a single-shot prompt-response. LangGraph gives you explicit state machines/graphs over this loop instead of an implicit agent loop.

Prompt engineering, scoped

Structuring prompts for reliable, parseable output — role/system prompts, few-shot examples, explicit output schemas, token-efficiency. Not "magic phrasing," it's treating the prompt as an API contract.

Where this maps to insurance

Document understanding (policy PDFs → structured fields), underwriting assistance (risk signals from unstructured text), claims triage (classify/summarize incoming claims). Your FOMC project — dense jargon-heavy docs → structured queryable data — is explicitly "the same class of problem," per your own resume. Say that line almost verbatim if asked why you're a fit.

Drill

RAGWhy does RAG reduce hallucination compared to asking the base model directly?
It grounds generation in retrieved, verifiable source text instead of relying purely on the model's parametric memoryThe model still generates language, but it's summarizing/synthesizing given context rather than recalling (and possibly misremembering) facts baked into its weights during training.
Agentic AIWhat's the concrete difference between a single-shot RAG pipeline and an agentic system, in terms of control flow?
Single-shot: one retrieve → one generate. Agentic: the model can decide to retrieve again, call a different tool, or decompose the task into subtasks, based on intermediate resultsThis is literally what your RLM project benchmarks — it explicitly beat single-shot RAG on multi-step queries because it could re-explore instead of committing to one retrieval pass.
Vector searchWhat does cosine similarity measure, and why is it preferred over Euclidean distance for text embeddings?
The angle between two vectors, ignoring magnitudeEmbedding magnitude often correlates with things like text length rather than semantic content, so comparing direction (cosine) is more robust than raw distance for meaning-similarity.
Prompt engineeringGive one concrete technique for making an LLM's output reliably parseable by downstream code.
Force a structured output schema — e.g. explicit JSON schema in the system prompt, or function/tool-calling if the API supports it — plus 1–2 few-shot examples of the exact format"Just ask it nicely for JSON" is a weak answer; naming schema-constrained generation or function calling shows you've actually shipped this, which you have.

07System design fundamentals

JD's own words: "think in systems, not just functions." Given their stated architecture (event-driven, modular, multi-tenant, Azure), expect conceptual questions, not a full whiteboard design round — an Engineer Trainee round rarely does a senior-level system-design interview, but should be able to reason about these terms correctly.

Event-driven architecture

Components communicate via events/messages (queue or pub-sub) instead of direct synchronous calls. Decouples producers from consumers, improves scalability and fault isolation — a slow consumer doesn't block the producer.

Modularity

System decomposed into components with clear boundaries and single responsibilities, communicating through well-defined interfaces. Lets teams build/deploy/scale pieces independently — directly tied to "building platforms, not just features."

Multi-tenancy

One deployed system serves multiple customers (tenants) with logically isolated data/config, sharing infrastructure. Core question to be ready for: "how do you keep Tenant A's data from leaking into Tenant B's queries" — row-level tenant_id scoping, separate schemas, or separate DBs, each a real trade-off.

REST API design basics

Resource-oriented URLs, correct HTTP verbs (GET/POST/PUT/DELETE), status codes that mean something (200/201/400/401/404/500), statelessness. JD explicitly names "clear understanding of APIs" — don't fumble a basic REST question.

Scalability levers

Horizontal (more instances) vs vertical (bigger instance) scaling, caching (you already know this from Redis), load balancing, async processing for slow operations (e.g. document analysis) instead of blocking the request thread.

Drill

Event-drivenWhy would BluePond process an uploaded insurance document asynchronously via an event queue rather than synchronously in the API request?
Document/LLM analysis is slow and variable-latency — blocking the HTTP request would time out or tie up server resourcesInstead: API accepts the upload, emits an event, returns immediately (e.g. 202 Accepted), and a background worker processes it, updating status the client can poll or get notified on. This is the same event-driven task-queue pattern your own RLM project already uses.
Multi-tenancyName two ways to isolate tenant data in a shared database, and one trade-off each.
(1) Shared schema with a tenant_id column on every table — cheap, simple, but a missing WHERE clause anywhere is a data leak. (2) Separate schema/DB per tenant — strong isolation, but higher operational overhead as tenant count grows.
RESTA client requests a resource that doesn't exist. A client sends malformed input. What status codes, and why does the distinction matter?
404 Not Found vs 400 Bad RequestCollapsing both into a generic error (or worse, 200 with an error body) makes the API impossible to handle programmatically on the client side — a real backend-hygiene signal interviewers check for.

08Coding practice

These are not predicted BluePond questions — there is no source for that. They're fundamentals-level practice sized to what "strong DS fundamentals + comfortable in Python" plausibly means for a trainee round, solvable in 20–25 min each.
Q1 · Hash mapGroup Anagrams. Given a list of strings, group the ones that are anagrams of each other. E.g. ["eat","tea","tan","ate","nat","bat"] → [["eat","tea","ate"],["tan","nat"],["bat"]].
Key each word by its sorted-character tuple (or a 26-length character-count tuple for O(k) instead of O(k log k) keying). Group into a defaultdict(list) by that key, one pass. O(n·k log k) time with sorted keys (n words, avg length k), O(n·k) space.
Q2 · Sliding windowLongest substring without repeating characters. Given a string, return the length of the longest substring with all unique characters.
Variable sliding window with a set/dict tracking the last-seen index of each character. Expand right; if the current char was seen inside the current window, jump the left boundary past its last occurrence. Track max window size seen. O(n) time, O(min(n, charset)) space.
Q3 · Two pointers / stackValid parentheses / balanced brackets. Given a string of (){}[], determine if it's balanced.
Push opening brackets onto a stack. On a closing bracket, pop and check it matches the corresponding opener; mismatch or empty-stack-pop → invalid. Valid iff the stack is empty at the end. O(n) time, O(n) space worst case. Classic "do you actually know when to reach for a stack" check.
