🔴 Operational traps — worth more than any topic

1. You cannot edit your code after compiling it.

Straight from 2025 candidates: "if you write a code and compile it and you find some errors then you cannot edit the code. You need to reset the code and type again. You cannot even copy your previous code and paste it."

What this means for you: compiling is nearly one-shot. Do not use the compiler as a debugger — the usual write-a-bit/compile/fix loop will destroy you here. Write the whole solution, dry-run it on paper against the sample input, re-read it line by line, then compile. This is the single highest-value habit to rehearse in the next two days.

2. You CAN switch between Foundation sections — most people don't know.

Reported directly: "Many students were not aware that they can switch between the sections for Foundation sections hence wasted time." Start with your strongest Foundation section, bank the marks, then move. Don't grind Numerical in order while Verbal marks go unclaimed.

3. Advanced sections are "Fill Up the Box" — no options.

Most Advanced Quant/Reasoning questions have no multiple choice — you type the answer directly. So back-solving from options, plugging in choices, and elimination do not work there. You must actually compute. Budget accordingly: these are marked Hard.

★ Verbal — two unusual formats worth real prep

This section is 26 minutes and contains no reading-comprehension MCQs. Two of its three parts are production tasks (you write), not recognition tasks (you pick). Those reward preparation far more than ordinary verbal questions do — which is why this moved up the priority order.

1 · Email Writing — 9 minutes, one item

The single longest-duration item in the entire Verbal section. You're given a scenario plus a set of keywords/phrases that must all appear in your email. Marking is largely mechanical: keyword coverage, correct email structure, grammar, and length.

The template — memorise this shape: 
Dear [Name / Sir / Madam],

[1 — Purpose] I am writing to ...

[2 — Body] ... weave in EVERY given keyword here ...
           ... 2-3 sentences, one idea each ...

[3 — Action/Close] I would be grateful if you could ...
                   Please let me know if you need any further details.

Regards,
[Your Name]
How to spend the 9 minutes:
  1. 0:00-1:00 — Read the scenario. Write the keyword list down (on rough sheet) and tick each as you use it.
  2. 1:00-6:30 — Write the email using the template. Aim 80-120 words unless told otherwise.
  3. 6:30-8:00 — Check every keyword is present. This is the most mechanically-scored part — missing one is a guaranteed lost mark.
  4. 8:00-9:00 — Proofread: tense consistency, subject-verb agreement, spelling, capital letters.
Rules that cost marks:
  • Use every single keyword — inflected forms are usually fine (inform → informed) but keep them recognisable.
  • Always include salutation and sign-off. A missing "Regards," is free marks lost.
  • Stay formal — no contractions (I am, not I'm), no slang, no emojis.
  • Don't pad to hit a word count — grammar errors cost more than brevity.
  • Keep sentences short. Short sentences are easier to keep grammatical under time pressure.

2 · Passage Recall — 30s read, then the text vanishes, 90s write

This is a memory test disguised as a verbal question.

You get 30 seconds to read, the passage is then removed from the screen, and you have 90 seconds to write. You cannot re-read. Most people fail this by reading normally and retaining nothing specific.

What to do in the 30 seconds — do NOT read for pleasure, read for capture:
  1. Scan for the skeleton first: Who? What happened? Where/When? Why?
  2. Grab concrete anchors — names, numbers, dates, places. These are what recall questions ask about, and they're the first things memory loses.
  3. If a rough sheet is allowed, jot 4-6 keywords immediately — not sentences, just anchors: Ravi · 2019 · Delhi · 40% rise · export ban. That skeleton regenerates the whole passage later.
  4. Read the first and last sentence carefully — they usually carry the main idea and conclusion.
In the 90 seconds of writing: lead with the main idea in one sentence, then the supporting facts in the order they appeared. Use your own words — paraphrase is fine and faster than reconstructing exact phrasing. Write something for every item; partial recall scores, blank does not.

3 · Sentence Completion — 20 items at 25 seconds each

Fast and mechanical. 25 seconds is not long — roughly, read the sentence once, pick, move.

Method: read the full sentence first and predict the missing word before looking at the options — then find the closest match. Predicting first stops good-looking distractors from anchoring you.

Watch for: connectives that flip meaning (however, although, despite, nevertheless = contrast; therefore, thus, hence = consequence). Getting the direction right usually eliminates half the options instantly.

No negative marking → never leave one blank. If you're stuck at 20 seconds, guess and move.

Tier A — closest to today's exam practise these

Set-2 style problems. These are the shape of a modern medium/hard NQT question — real data structures and multi-step logic.

  • Balanced parentheses — return count if balanced, −1 if not (stack)
  • Reverse the second half of a linked list (odd length → middle counts as second half)
  • Merge two sorted linked lists into one sorted list
  • Reverse a linked list — both recursive and iterative
  • Merge sort using pointers
  • Search a 2D matrix for a target, return coordinates, (−1,−1) if absent
  • Merge two arrays removing duplicates — output merged set + total count
  • Count occurrences of a digit in a number (isOccured(num1, num2))
  • Find and replace a substring within a string
  • Print/count all numbers less than a key in an array
  • Sort an array into two halves — first ascending, second descending
  • Remove vowels from a string using pointers / via a function call
  • Largest or second-largest among N inputs

Tier B — plausible as the easier Q1 skim, don't drill

  • String palindrome · number palindrome (5-digit, print YES/NO uppercase)
  • String reversal without library functions · string compare without strcmp
  • Sum of all primes in a range (bounds exclusive) · sum of odd numbers in a range
  • Nth Fibonacci / Fibonacci series to N terms
  • Armstrong number · perfect number · prime check (print √n if prime else 0.00)
  • Binary↔decimal, decimal↔octal, binary↔octal conversions
  • GCD and LCM of two numbers
  • Square root without sqrt()

Tier C — outdated, skip 2019 era only

Area of circle/triangle from given dimensions, hypotenuse, factorial, leap year, temperature conversion, reverse digits, command-line-argument programs. These were the whole coding round in 2019. Today they'd be a warm-up at best — and command-line arguments are no longer used (input comes from STDIN).

Formatting rules TCS actually enforces

Marks are genuinely lost here, and the old papers are consistent about it:

  • Read from STDIN, write to STDOUT. No command-line arguments.
  • Print nothing extra — no "Enter a number:" prompts. Hidden test cases do exact matching, so a stray prompt fails everything.
  • Case matters — YES/NO in uppercase when specified.
  • Float precision — "exactly 2 decimal places" means f"{x:.2f}", and never scientific notation.
  • Edge cases they actually test: 0! = 1 was a hidden test case in a real factorial question. Always handle 0, empty input, and single-element cases.

Exam day (17 Aug) — the six rules

  1. Read the opening instructions. They tell you whether you can switch between sections — your pattern lists the groups flat, so this is genuinely unknown until you're in. If you can switch, start with your strongest.
  2. Never leave a blank. No negative marking, so an unanswered MCQ is strictly worse than a guess.
  3. Coding: the compiler is a verifier, not a debugger. Write it fully, dry-run on paper, then compile. You cannot edit after compiling — you have to reset and retype from scratch.
  4. Use Python. Fewest characters to retype if you're forced to reset, and it's your primary language.
  5. Print nothing extra. No "Enter a number:" prompts — hidden tests do exact matching. Watch uppercase YES/NO and .2f precision when specified.
  6. Email: tick every keyword before you submit. That's the most mechanically-scored thing on the paper, and the easiest to lose by forgetting one.
