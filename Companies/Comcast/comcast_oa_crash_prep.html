Agents & automation — the reason they're hiring

What is an AI agent, vs. a single LLM call?
Reveal

An agent plans, calls tools, observes the result, and iterates in a loop until a goal is met — instead of a one-shot prompt→response. Key components: an LLM as the reasoning core, tool/function calling, memory (short-term context + long-term store), and a control loop. Your line: "In A.R.G.U.S-V I orchestrated retrieval agents with LangGraph, which gives you an explicit state graph over that loop rather than an opaque agent framework."

How would you build an agent to automate a business workflow?
Reveal

Define the goal and success criteria → expose the systems as tools with typed schemas (APIs, DB queries) → let the LLM plan and select tools → validate every output before it takes effect → add a human-in-the-loop gate for irreversible actions → log every step for auditability. Say the safety part out loud — for a company automating real operations, "what happens when the agent is wrong" is the mature answer that separates you from a candidate reciting LangChain tutorials.

What is RAG and why use it?
Reveal

Retrieval-Augmented Generation: embed a query → semantic search over a vector store → inject retrieved chunks into the prompt → generate grounded in that context. Benefits: reduces hallucination, adds private/fresh knowledge without retraining, and gives you citable sources. Your line: "I reproduced a recursive-LM paper and benchmarked it against a single-shot RAG baseline — 3/3 vs 0/3 on multi-step queries."

Fine-tuning vs. RAG vs. prompt engineering — when do you pick each?
Reveal

Prompting: cheapest, no training, first thing to try. RAG: when the model needs knowledge it doesn't have (private/changing data) — no weight updates. Fine-tuning: when you need to change behaviour, style, or format consistently, not just add facts. Rule of thumb: RAG for knowledge, fine-tuning for behaviour. Very common interview question.

What are embeddings and vector databases?
Reveal

Embeddings map text/images to dense vectors where semantic similarity ≈ geometric closeness (cosine similarity). Vector DBs (LanceDB, Pinecone, FAISS, Redis) index these for fast approximate nearest-neighbour search. Cosine over Euclidean because magnitude often tracks text length, not meaning. You've used LanceDB and Redis — name them.

Hallucination — what causes it, how do you reduce it?
Reveal

Cause: the model predicts plausible tokens from parametric memory with no grounding or truth check. Mitigations: RAG grounding, citation requirements, lower temperature, structured/schema-constrained output, self-consistency checks, and validation against a source of truth before acting.

Core ML — likely MCQ territory

Supervised vs Unsupervised vs ReinforcementSupervised: labelled data (classification/regression). Unsupervised: no labels, find structure (clustering, PCA). RL: agent learns from reward signal through interaction.
Overfitting vs UnderfittingOverfit: low train error, high test error — memorised noise. Underfit: high error both — model too simple. Fixes for overfit: more data, regularisation (L1/L2), dropout, early stopping, cross-validation.
Bias-Variance tradeoffHigh bias = underfitting (too simple). High variance = overfitting (too sensitive to training data). Total error = bias² + variance + irreducible noise.
Train / Validation / TestTrain: fit weights. Validation: tune hyperparameters, select model. Test: final unbiased estimate, touched once. Leaking test into tuning is the classic mistake.
Precision vs RecallPrecision = TP/(TP+FP) — of what I flagged, how much was right. Recall = TP/(TP+FN) — of what existed, how much did I catch. F1 = harmonic mean. Accuracy misleads on imbalanced data.
L1 vs L2 regularisationL1 (Lasso): drives weights to exactly zero → feature selection. L2 (Ridge): shrinks weights smoothly, doesn't zero them.
Gradient descentIteratively step weights opposite the loss gradient. Batch (all data), Stochastic (one sample), Mini-batch (standard compromise). Learning rate too high → diverges; too low → crawls.
Confusion matrixTP / FP / FN / TN. Be able to compute precision, recall, accuracy from a given matrix — a very common MCQ format.

Deep learning — you have a real edge here

Explain the transformer architecture / self-attention.
Reveal

Self-attention lets every token attend to every other token directly: compute Query, Key, Value projections, score = softmax(QKᵀ/√d_k), output = score·V. Multi-head runs several attention subspaces in parallel. Positional encodings inject order (attention itself is permutation-invariant). Advantage over RNNs: parallelisable and no long-range dependency decay. Your line: "I implemented this from first principles in PyTorch — MLP blocks, single- and multi-head attention, full decoder stack, no high-level model libraries — and trained a 13M-parameter model on The Pile to coherent generation."

Why √d_k in the attention scaling?
Reveal

Dot products grow with dimension; large values push softmax into saturated regions where gradients vanish. Dividing by √d_k keeps variance ~1 so gradients stay usable. A great "did you actually implement it" discriminator — and you did.

Activation functionsReLU: max(0,x), cheap, can "die". Sigmoid: (0,1), saturates/vanishing gradient. Tanh: (-1,1), zero-centred. Softmax: converts logits to a probability distribution over classes.
Vanishing / exploding gradientsDeep nets multiply gradients through layers → shrink to 0 or blow up. Fixes: ReLU, residual/skip connections, batch/layer norm, careful init, gradient clipping.
CNN vs RNN vs TransformerCNN: spatial/local features (images). RNN/LSTM: sequential, has memory, hard to parallelise. Transformer: attention-based, parallel, dominant for sequences now.
DropoutRandomly zeroes activations during training to prevent co-adaptation; disabled at inference (weights scaled). A regularisation technique.
Batch normalisationNormalises layer inputs per mini-batch → faster, more stable training, mild regularisation. LayerNorm (per-sample) is what transformers use instead.
Epoch vs Batch vs IterationEpoch: one full pass over the dataset. Batch: samples per weight update. Iteration: one update. iterations/epoch = dataset size ÷ batch size.

SQL Drill — the highest-confidence topic

Both reports call out SQL explicitly, including "write 5 queries, joins + subqueries" live in the technical interview. Assume you'll be asked to write SQL by hand, not just recognize it in an MCQ.

Schema: employees(id, name, dept_id, salary, manager_id), departments(id, name)
Q1. List each department's name with its average salary, only for departments with more than 3 employees.
Reveal answer 
SELECT d.name, AVG(e.salary) AS avg_salary
FROM departments d
JOIN employees e ON e.dept_id = d.id
GROUP BY d.name
HAVING COUNT(e.id) > 3;

HAVING filters after GROUP BY (WHERE can't reference an aggregate). Common trap: using WHERE COUNT(...) — that fails.

Same schema
Q2. Find employees who earn more than their own manager.
Reveal answer 
SELECT e.name
FROM employees e
JOIN employees m ON e.manager_id = m.id
WHERE e.salary > m.salary;

Self-join — the same table joined to itself via manager_id → id. This exact shape ("compare a row to a related row in the same table") is a classic Comcast-style ask.

Same schema
Q3. List employees who earn more than the average salary of their own department, using a subquery (not a window function).
Reveal answer 
SELECT e.name
FROM employees e
WHERE e.salary > (
  SELECT AVG(e2.salary) FROM employees e2 WHERE e2.dept_id = e.dept_id
);

Correlated subquery — the inner query re-runs per outer row, referencing the outer row's dept_id. This is the "subqueries" half of "joins and subqueries" — practice this shape specifically.

Same schema
Q4. List departments with no employees at all.
Reveal answer 
SELECT d.name
FROM departments d
LEFT JOIN employees e ON e.dept_id = d.id
WHERE e.id IS NULL;

LEFT JOIN + IS NULL is the standard "find the missing side" pattern — an INNER JOIN here would silently drop empty departments instead of surfacing them.

Same schema
Q5. Get the second-highest salary in the company without using LIMIT/OFFSET.
Reveal answer 
SELECT MAX(salary) AS second_highest
FROM employees
WHERE salary < (SELECT MAX(salary) FROM employees);

Nested MAX — a very common "gotcha" SQL question precisely because LIMIT/OFFSET isn't portable across every DB engine.

Java / C / C++ — output traps (newly confirmed in scope)

Java — == vs .equals()== compares references; .equals() compares content. new String("a") == new String("a") is false. But string literals are interned, so "a" == "a" is true. Classic MCQ.
Java — Integer cachingInteger a=127, b=127; a==b → true (cached -128..127). Integer a=128, b=128; a==b → false. Pure trap question.
Java — overloading vs overridingOverloading: same name, different params, resolved at compile time. Overriding: subclass redefines a parent method, resolved at runtime (dynamic dispatch).
Java — String immutabilityStrings are immutable; every "modification" makes a new object. Use StringBuilder for loops of concatenation (else O(n²)).
C — i++ vs ++iPost-increment returns the old value then increments; pre-increment increments then returns. int i=5; printf("%d", i++ + ++i); is undefined behaviour — multiple modifications between sequence points.
C — pointer arithmeticptr+1 advances by sizeof(*ptr) bytes, not 1 byte. Array name decays to a pointer to its first element; sizeof(arr) on an array gives total bytes, but on a pointer gives pointer size.
C — integer division & promotion5/2 == 2 (int division), 5/2.0 == 2.5. Mixing signed/unsigned promotes to unsigned — -1 < 1u is false.
C++ — pass by value/reference/pointerValue: copies. Reference (&): alias, no copy, can't be null/reseated. Pointer: can be null, can be reassigned. Prefer const& for large read-only params.
C++ — virtual functionsvirtual enables runtime polymorphism via the vtable. A base class with virtual methods needs a virtual destructor, else deleting via base pointer leaks the derived part.
C++ — static vs dynamic allocationStack: automatic, scope-bound, fast. Heap (new/malloc): manual lifetime, must free/delete. Prefer smart pointers (unique_ptr, shared_ptr) in modern C++.

Core subjects

DBMS — Normalization1NF: no repeating groups. 2NF: no partial dependency on a composite key. 3NF: no transitive dependency on a non-key column. Know why you'd denormalize anyway (read-heavy, avoid join cost).
DBMS — ACIDAtomicity, Consistency, Isolation, Durability. Isolation levels: Read Uncommitted → Read Committed → Repeatable Read → Serializable, each fixing a specific anomaly (dirty read, non-repeatable read, phantom read).
OS — DeadlockFour necessary conditions: mutual exclusion, hold-and-wait, no preemption, circular wait. Break any one → no deadlock.
OS — Process vs ThreadProcess: own memory space, heavyweight context switch. Thread: shares memory with siblings, lightweight switch. Threads within a process share heap/data, each has its own stack.
OS — Paging vs SegmentationPaging: fixed-size blocks, no external fragmentation, may have internal fragmentation. Segmentation: variable-size logical units, opposite trade-off.
CN — TCP vs UDPTCP: connection-oriented, reliable, ordered, slower (3-way handshake). UDP: connectionless, no guarantee, faster — used where speed beats reliability (video/voice).
CN — OSI layersPhysical → Data Link → Network → Transport → Session → Presentation → Application ("Please Do Not Throw Sausage Pizza Away"). Know which layer does what: IP=Network, TCP/UDP=Transport, HTTP=Application.
CN — DNSResolves domain name → IP address, hierarchical (root → TLD → authoritative), cached at multiple levels (browser, OS, resolver).
DS — Array vs Linked ListArray: O(1) random access, O(n) insert/delete mid-sequence. Linked List: O(n) access, O(1) insert/delete at a known node. Know when each wins.
DS — Stack vs Queue use casesStack: LIFO — undo, recursion/call stack, balanced-brackets. Queue: FIFO — BFS, task scheduling, print spooling. This exact question ("describe two data structures with a real example") was asked verbatim in one report.
Linux — basic commandsgrep (search text), chmod (permissions), ps/top (processes), kill -9 (force-terminate), chmod 755 means owner rwx, group/others r-x.
Linux — permissionsrwxr-xr-- reads as owner=rwx, group=r-x, others=r--. Numeric: r=4, w=2, x=1, sum per triplet.

Coding — easy-medium, matching reported topics

Not predicted verbatim questions — practice problems in the same shape as what both reports named: palindrome check, "second maximum element," sorting complexity.

Q1 · Palindrome check — Given a string, determine if it's a palindrome, ignoring case and non-alphanumeric characters.
Reveal approach

Two pointers from both ends, skip non-alphanumeric, compare lowercased chars, converge to the middle. O(n) time, O(1) space. The named report explicitly expects a two-pointer solution — don't reach for string reversal + comparison, name the two-pointer approach out loud.

Q2 · Second maximum element — Given an array, find the second-largest element without sorting.
Reveal approach

Single pass, track max1 and max2. If current > max1: max2 = max1, max1 = current. Else if current > max2 and current != max1: max2 = current. O(n) time, O(1) space — sorting would be O(n log n), a slower "correct but suboptimal" answer they're explicitly testing for.

Q3 · Sorting complexity, cold — State time/space complexity (best/avg/worst) for Bubble Sort, Merge Sort, Quick Sort, and when you'd pick each.
Reveal answer

Bubble: O(n²) all cases, O(1) space — never use it, know why it's bad. Merge: O(n log n) all cases, O(n) space — stable, good for linked lists / external sorting. Quick: O(n log n) avg, O(n²) worst (bad pivot), O(log n) space — fastest in practice, in-place. "Different sorting algorithms, be good at time/space complexity" was named directly in one report.
