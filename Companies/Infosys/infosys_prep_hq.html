🔴 The one fact that changes how you sit this exam

Infosys has SECTIONAL CUT-OFFS. TCS did not.

Every section is independently qualifying. A brilliant quant score cannot rescue a failed pseudocode section — you are rejected on the weak section regardless of your total.

What this means: your TCS strategy was maximise total marks. That strategy is wrong here and will get you rejected. The correct strategy is clear every floor first, optimise second. Spend your last minutes in your weakest section, not your most profitable one.

Each section is SEPARATELY TIMED — you cannot bank time.

The per-section clocks are wildly uneven, and that's the whole pacing game:

★ Pseudocode drill — 10 traced questions

Format reminder: you are given a C-like block and asked what it prints. You never write code. Every answer below has been executed and verified, not eyeballed.

Method — use paper (it's allowed): draw a column per variable, one row per loop iteration, and fill it in. Tracing in your head is where people lose this section. On ~5 questions with a sectional cut-off, one careless trace is expensive.

Q1 — XOR swap

int a = 5, b = 3;
a = a ^ b;
b = a ^ b;
a = a ^ b;
print(a, b);
3 5 — the classic XOR swap idiom. It exchanges the two values without a temp variable. Recognise the three-line shape on sight and you don't need to trace it at all.

Q2 — alternating sign accumulation

int arr[] = {2, 4, 6, 8, 10};
int s = 0;
for(i = 0; i < 5; i++) {
    if(i % 2 == 0) s = s + arr[i];
    else           s = s - arr[i];
}
print(s);
6 — the condition tests the index, not the value. +2 −4 +6 −8 +10 = 6. Misreading i%2 as "even elements" is the trap.

Q3 — recursion

int f(int n) {
    if(n <= 1) return n;
    return f(n-1) + f(n-2);
}
print(f(6));
8 — Fibonacci with f(0)=0, f(1)=1. Sequence: 0,1,1,2,3,5,8. Build the table upward from the base case; never expand the recursion tree by hand.

Q4 — loop with a non-unit step

int i = 0, c = 0;
while(i < 20) {
    if(i % 3 == 0) c++;
    i = i + 2;
}
print(c);
4 — i takes 0,2,4,…,18. Of those, divisible by 3: 0, 6, 12, 18. Note 0 counts — forgetting that 0 % 3 == 0 is the most common miss here.

Q5 — character counting

char s[] = "INFOSYS";
int c = 0;
for(i = 0; s[i] != '\0'; i++)
    if(s[i]=='S' || s[i]=='O' || s[i]=='I') c++;
print(c);
4 — I·N·F·O·S·Y·S → I(1) + O(1) + S(2) = 4. The duplicate S is the point; count occurrences, not distinct letters.

Q6 — triangular nested loop

int c = 0;
for(i = 1; i <= 4; i++)
    for(j = i; j <= 4; j++)
        c++;
print(c);
10 — inner loop starts at i, not 0, so iterations are 4+3+2+1 = 10. Any j = i inner loop is a triangular number: n(n+1)/2.

Q7 — pointer vs value parameter

void f(int *x, int y) {
    *x = *x + 10;
    y  = y  + 10;
}
int a = 5, b = 5;
f(&a, b);
print(a, b);
15 5 — x is a pointer so the write reaches the caller's a. y is a copy, so b is untouched. This pass-by-reference vs pass-by-value contrast is the single most common Infosys pseudocode question type — expect a version of it.

Q8 — in-place array mutation

int a[] = {1, 2, 3, 4, 5};
for(i = 0; i < 4; i++)
    a[i+1] = a[i+1] + a[i];
print(a[4]);
15 — the array is modified as it's read, producing a running prefix sum: 1, 3, 6, 10, 15. The trap is using the original values on the right-hand side. Always re-read the array as mutated.

Q9 — digit reversal

int n = 1234, r = 0;
while(n > 0) {
    r = r * 10 + n % 10;
    n = n / 10;
}
print(r);
4321 — n % 10 peels the last digit, n / 10 is integer division and drops it. Memorise this four-line shape as "reverse the digits"; it appears constantly.

Q10 — bit counting

int n = 29;
int c = 0;
while(n > 0) {
    c = c + (n & 1);
    n = n >> 1;
}
print(c);
4 — 29 in binary is 11101, which has four 1-bits. n & 1 reads the lowest bit, n >> 1 discards it. This is the standard population-count loop.

The five shapes that cover most of this section

  1. Pointer vs value — does the change escape the function? (Q7)
  2. Integer division truncates — 7/2 == 3, and digit-peeling loops rely on it (Q9)
  3. In-place mutation while iterating — later reads see earlier writes (Q8)
  4. Loop bounds and step — off-by-one, non-unit steps, inner loops starting at i (Q4, Q6)
  5. Bitwise idioms — XOR swap, &1 / >>1 bit walking (Q1, Q10)

If you can name which shape a question is within ten seconds, you'll clear this section. That recognition is worth more than tracing speed.

Puzzles + Grammar — the two cheap sections

Puzzle Solving ~4 questions

The recurring shapes:
  • Missing number in a series — test differences first, then ratios, then squares/cubes, then alternating series. Most are one of those four.
  • Number grid / sudoku-type — find the row or column with the most constraints and start there, never the top-left.
  • Pattern completion — check rotation, reflection, and element-count separately rather than looking at the figure as a whole.
  • Mathematical arrangement — placing digits to satisfy a sum. Work from the most constrained position (usually the carry).
Time rule: ~4 questions, and they're the easiest section to sink 8 minutes into for one mark. Give any single puzzle 90 seconds, then guess and move — there's no negative marking, and the sectional cut-off on 4 questions is low.

English Grammar ~5 questions, own cut-off

Discrete section, so it can fail you on its own despite being small. The reliable earners:
  • Subject-verb agreement — find the true subject; ignore everything between it and the verb ("The box of chocolates is…").
  • Tense consistency — one timeframe per sentence unless a marker says otherwise.
  • Prepositions — these are pure memorisation and the most commonly tested item. Skim a standard list once tonight.
  • Parallel structure — items in a list must share a form ("reading, writing, and to speak speaking").
  • Modifier placement — the modifier attaches to whatever it sits next to.

English Writing (essay) warm from TCS

Same production skill as the TCS email, different wrapper. Structure carries the marks: intro stating your position → 2 body paragraphs, one idea each → conclusion that resolves rather than repeats. Short grammatical sentences beat long ambitious ones. Leave 60 seconds to proofread for tense and agreement — the same two errors that cost marks in the grammar section cost marks here.

Your highest-probability way to lose a solved problem

On the TCS Easy this morning your logic was correct and the output format was wrong — you printed a Python dict repr {1: 1, 2: 1} where {1:1,2:1} was required. Exact-match hidden tests failed every case.

Amazon is also exact-match. The rule, drilled until reflexive:

#  NEVER print a container directly
print(d)                                   # {1: 1, 2: 1}   WRONG
print([50, 60])                            # [50, 60]       WRONG

#  Build the string yourself
print("{" + ",".join(f"{k}:{v}" for k,v in d.items()) + "}")
print("[" + ",".join(map(str, xs)) + "]")

Before submitting any problem: re-read the required output format, then compare it character by character against one line of your actual output.

Work Simulation / Leadership Principles

Not a personality test to game — but not free either. Two things reliably help:
  • Bias for Action: when a scenario offers "gather more data" vs "act now with what you have", Amazon's culture favours acting and iterating. Escalating or waiting reads as weak.
  • Ownership: never pick the option that hands the problem to another team. "Not my job" is the wrong answer in every scenario.
  • Be consistent. The survey repeats similar statements to detect contradictions. Answer as one coherent person, not as who you think they want per-question.
