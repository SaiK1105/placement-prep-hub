Grid Invasion (multi-source BFS) — 2025 P1 EASY #5

Solved live in tutoring, 17 Aug. Wave spreads from ALL 'A' cells at once; answer = the largest shortest-distance any 'E' sits from its nearest 'A'; -1 if any 'E' is never reached. Pattern: multi-source BFS, level = seconds. Key insight: seed the queue with every 'A' simultaneously — one BFS still gives each cell its distance to the NEAREST source. Count fresh 'E' cells up front; if converted count falls short, print -1. Verified: all 3 official samples ✓, degenerate grids ✓, 1000×1000 stress in 0.80s ✓. Trap: mark visited when you PUSH, not when you pop; and list.pop(0) is TLE — use deque.popleft().

from collections import deque

import sys
input = sys.stdin.readline
def Solve(n,m,grid):
        n = len(grid)
        m = len(grid[0])
        q = deque()
        visited = [[0]*m for _ in range(n)]
        cntFresh = 0
        for i in range(n):
            for j in range(m):
                if grid[i][j] == 'A':
                    q.append((i,j,0))
                    visited[i][j] = 1
                else:
                    visited[i][j] = 0
                if grid[i][j] == 'E':
                    cntFresh+=1
        tm = 0
        drow = [-1,0,1,0]
        dcol = [0,-1,0,1]
        cnt = 0
        while q:
            r,c,t = q.popleft()
            tm = max(tm,t)
            for i in range(0,4):
                nrow = r+drow[i]
                ncol = c+dcol[i]
                if 0<=nrow<n and 0<=ncol<m and grid[nrow][ncol] == 'E' and visited[nrow][ncol] == 0:
                    q.append((nrow,ncol,t+1))
                    visited[nrow][ncol] = 1
                    cnt +=1
        if cnt!=cntFresh :
            return -1
        return tm

n = int(input())
m = int(input())
grid = [input().strip() for _ in range(n)]
print(Solve(n,m,grid))```

### Unique Paths With Blockers (grid DP + mod) — Level-up Q9 "Hard"
**Solved live in tutoring, 17 Aug.** Count down/right paths avoiding walls, mod 1e9+7.
**Pattern:** grid-counting DP, row-major fill.
**Key insight:** ways(i,j) = ways(above) + ways(left); a wall holds 0 and vanishes from the arithmetic.
BFS can't count paths — its visited flag discards every arrival after the first.
**Verified:** all 3 samples ✓ (2, 1, 0), 1000×1000 open grid in 0.44s ✓.
**Trap:** `% MOD` on every sum — Python won't overflow, it will TLE on 600-digit integers instead.
```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

m, n = map(int, input().split())
grid = [list(map(int, input().split())) for _ in range(m)]

dp = [[0]*n for _ in range(m)]
dp[0][0] = 1

for i in range(m):
    for j in range(n):
        if grid[i][j] == 1:
            dp[i][j] = 0
            continue
        if i == 0 and j == 0:
            continue
        top = dp[i-1][j] if i > 0 else 0
        left = dp[i][j-1] if j > 0 else 0
        dp[i][j] = (top + left) % MOD

print(dp[m-1][n-1])

Food Stamps — 2026 Easy

Problem in one paragraph: N food types, buy up to M meals total (any mix), i-th purchase of type-i food's t-th time gives v[i] - d[i]*(t-1) taste points; maximize total points, never forced to buy a food with negative marginal points since M is a cap, not a quota. Reconstruction note: the PDF interleaves "Input Format"/"Constraints" between Case 2 and Case 3 — the statement, samples, and format were reassembled from context; no numeric values needed guessing.

Pattern: binary search on a value threshold to pick the top-M elements out of N decreasing arithmetic sequences (classic "top-K across many APs").

Key insight: A naive max-heap simulation is O(M log N) and M can be 1e9 — too slow. Instead binary-search the cutoff value T such that the count of all (item, purchase) pairs with value ≥ T is ≥ M; sum of an AP prefix is closed-form, so counting/summing per item is O(1) and one binary-search pass is O(N). If even all non-negative-value purchases (T=0) don't reach M, just take all of them — never take negative-value purchases since M is only an upper bound.

Walkthrough: Case 3 — v=[5,7,9], d=[2,4,6], m=5. Threshold search settles at T=3: values ≥4 are {9,7,5} (3 picks), values ≥3 add three more 3's (one per item's 2nd purchase) → cnt(3)=6 ≥5, cnt(4)=3 <5. So take the 3 items above T=3 (sum 21) plus (5-3)=2 more picks at value exactly 3 (sum 6) → 27. Matches expected output.

Solution (Python, tested):

import sys

def solve(n, m, v, d):
    def count_and_sum(T):
        total_cnt = 0
        total_sum = 0
        for vi, di in zip(v, d):
            k = (vi - T) // di + 1
            if k < 0:
                k = 0
            if k > 0:
                total_cnt += k
                total_sum += k * vi - di * (k * (k - 1) // 2)
        return total_cnt, total_sum

    cnt0, sum0 = count_and_sum(0)
    if cnt0 <= m:
        return sum0

    lo, hi = 0, max(v)
    while lo < hi:
        mid = (lo + hi + 1) // 2
        c, _ = count_and_sum(mid)
        if c >= m:
            lo = mid
        else:
            hi = mid - 1
    T = lo
    cntT1, sumT1 = count_and_sum(T + 1)
    remaining = m - cntT1
    return sumT1 + remaining * T

def main():
    data = sys.stdin.read().split()
    idx = 0
    n = int(data[idx]); idx += 1
    m = int(data[idx]); idx += 1
    v = [int(data[idx + i]) for i in range(n)]; idx += n
    d = [int(data[idx + i]) for i in range(n)]; idx += n
    print(solve(n, m, v, d))

if __name__ == "__main__":
    main()

Complexity: O(N log(max V)) time, O(1) extra space. Trap: don't simulate purchase-by-purchase — M up to 1e9 makes a heap loop TLE; also never let the count function go into negative-value territory when the positive supply already falls short of M.

Verified: Case1 → 5 ✓, Case2 → 12 ✓, Case3 → 27 ✓ (all three sample cases matched exactly).

MSS with Exactly K Swaps — 2026 Easy/Medium

Problem in one paragraph: Array of length N (≤500) and integer K; perform exactly K swap operations (any two indices, repeats allowed and cancel in pairs, so it's "at most K useful swaps"); maximize the maximum subarray sum of the final array. Reconstruction note: Case 2's sample (k=0, a=[5,-1,5]) has its actual expected output missing/misplaced in the scrambled PDF — the "Output: 2 / sum of [2]" text directly following it is a duplicate of Case 3's explanation, not Case 2's real answer. I treated Case 2 as unverifiable from the source and instead sanity-checked my program on it directly.

Key insight: For a fixed target subarray [l, r], the best you can do with ≤K swaps is: sort the subarray ascending and everything outside it descending, then greedily replace the smallest inside elements with the largest outside elements one pair at a time, only while the outside value beats the inside value and swaps remain (classic exchange argument — this is optimal for that fixed range). The overall answer is the max over all O(N²) choices of [l, r].

Walkthrough: Case 1 — n=3, k=1, a=[1,-5,2]. Try [l,r]=[1,1] wait, best range is the single index 1 (0-indexed) initially -5: outside={1,2} desc=[2,1], swap -5↔2 (2>-5, beneficial) → subarray value becomes 2, one swap used. But trying [l,r]=[0,2] (whole array) inside sorted=[-5,1,2], outside=[] (nothing to swap in) → sum=-2. Trying [l,r]=[2,2] alone =2 already, no swap needed. Best over all ranges after applying the swap rule is 3, achieved at [l,r]=[1,2] (inside=[-5,2] sorted=[-5,2], outside=[1], swap -5↔1 → subarray becomes [1,2] sum=3). Matches expected output 3.

Solution (Python, tested):

import sys

def solve(n, k, a):
    best = -10**18
    for l in range(n):
        for r in range(l, n):
            inside = sorted(a[l:r+1])
            outside = sorted(a[:l] + a[r+1:], reverse=True)
            s = sum(inside)
            swaps = 0
            ii = 0
            for oi in range(len(outside)):
                if swaps >= k or ii >= len(inside):
                    break
                if outside[oi] > inside[ii]:
                    s += outside[oi] - inside[ii]
                    swaps += 1
                    ii += 1
                else:
                    break
            best = max(best, s)
    return best

def main():
    data = sys.stdin.read().split()
    n = int(data[0]); k = int(data[1])
    a = [int(x) for x in data[2:2+n]]
    print(solve(n, k, a))

if __name__ == "__main__":
    main()

Complexity: O(N² · N log N) as written (sorts inside the double loop) — correct but not tuned; for N=500 this is safe for a 3-hour exam only if the judge's time limit is generous. A faster O(N² log N) version (incrementally maintaining sorted inside/outside sets as r grows via bisect.insort) is the upgrade path if TLE is observed. Trap: the swap pool is the whole array outside [l,r], not just adjacent elements — and stop swapping the instant the best outside value no longer beats the worst inside value, even if swaps remain (extra swaps can only be forced to be no-ops via the "double-swap cancels" rule, never harmful, but also never helpful once no beneficial pair remains).

Verified: Case1 (k=1, a=[1,-5,2]) → 3 ✓. Case3 (k=0, a=[1,-5,2]) → 2 ✓. Case2 as literally given (k=0, a=[5,-1,5]) is not reliably reconstructable from the scrambled source; my program returns 9 (the whole-array sum, correct by direct hand-check since k=0 means no rearrangement is possible) — treat this as a self-derived check, not a matched official sample.

Lock & Key Parity — 2026 Hard

Problem in one paragraph: N locks (≤200) in a row, each with value L[i]; assign key j to lock i only if j<i and L[j]≠L[i], at cost |L[j]-L[i]|; each key/lock used at most once; a chosen assignment set is valid only if even_count ≥ odd_count (by parity of cost) and at least one assignment is made; minimize total cost, or -1 if impossible. Reconstruction note: this problem's explanation blocks are correctly ordered in the source but its "Input Format/Constraints" box is sandwiched mid-explanation by the scramble — content itself was intact, just needed reordering.

Pattern: every collapse-to-one-edge exchange argument — all costs are strictly positive, so adding assignments never lowers the sum.

Key insight: Since |L[j]-L[i]| is always ≥1 (L[j]≠L[i] required) and the parity constraint even ≥ odd is already satisfied by a single even-cost assignment (1 even ≥ 0 odd), and every extra assignment only adds positive cost, the minimum-cost valid set is always just the single cheapest valid pair (j<i, L[j]≠L[i]) whose |diff| is even. If no even-parity pair exists at all, no valid set can exist (a lone odd assignment always violates even≥odd, and stacking more odds only makes it worse) → answer -1.

Walkthrough: Case 1 — L=[41,54,15,4,54,4]. Every even-cost pair's cost is computed; the cheapest is (1→3): |41-15|=26 (even). No even pair costs less than 26 (next-cheapest even pairs are 50). So answer = 26, exactly matching the sample's chosen single assignment.

Solution (Python, tested):

import sys

def solve(n, L):
    best = None
    for i in range(n):
        for j in range(i):
            if L[j] == L[i]:
                continue
            diff = abs(L[j] - L[i])
            if diff % 2 == 0:
                if best is None or diff < best:
                    best = diff
    return best if best is not None else -1

def main():
    data = sys.stdin.read().split()
    n = int(data[0])
    L = [int(x) for x in data[1:1 + n]]
    print(solve(n, L))

if __name__ == "__main__":
    main()

Complexity: O(N²) — trivially fine for N≤200. Trap: don't build a full min-cost matching/flow model — the positive-cost + "single edge already satisfies the parity inequality" observation collapses the whole assignment problem to "cheapest even-parity pair, or -1."

Verified: Case1 → 26 ✓, Case2 → 30 ✓, Case3 → 24 ✓ (all three sample cases matched exactly).

Layer-Split Path Maximization with Penalties — 2026 Complex

Problem in one paragraph: Undirected graph, N,M ≤1e5, each node has a layer 1..K and a value; find a simple path whose layer sequence is non-decreasing, maximizing (sum of values on path) − Σ(layer jump)² over each strict layer increase along the path. This section of the source read cleanly (no scramble artifacts noticed).

Approach sketch (not tested — Complex tier, skip if time-constrained): - Because the path's layers must be non-decreasing, only edges that go from a lower-or-equal layer to a higher-or-equal layer are ever usable in a valid path direction; this induces a DAG-like traversal order except when multiple nodes share the exact same layer and are connected — those same-layer components can still contain cycles in the original graph, and a simple path restricted to a general graph with cycles is NP-hard in general. The tractable version (and almost certainly the intended one) assumes you only need the best simple path within each same-layer connected component (likely small/tree-like in the intended test data) combined with a longest-path DP across layer-strata. - Core recurrence (assuming same-layer components are trees, i.e. no exploitable cycles): process nodes in increasing layer order; best[u] = max value obtainable ending exactly at u. Within a layer, propagate along same-layer tree edges without penalty (still must stay simple — a single DFS/BFS "best chain ending at each node" walk works because it's a tree). When moving from layer x to a strictly greater layer y via an edge, the arriving value is best[u] + V[v] - (y-x)^2. - Take best[u] as candidates going both directions per component, similar to "diameter of a tree with weighted node values", then relax cross-layer edges in increasing-layer topological order (Dijkstra-like relaxation but on a DAG so a single sorted-by-layer pass suffices). - Answer = max over all nodes of best[u] (a path can be a single node).

Complexity: O((N+M) log K) if implemented as a layered DAG longest-path relaxation; the same-layer-cycle case (if it occurs in real test data) would need SCC condensation first, adding O(N+M) — feasible but meaningfully more code than budget allowed here.

Trap: don't forget a path can be a single node (Case 3 shows the optimal answer skips connecting negative-value neighbors entirely) — always include the empty-penalty single-node values as base cases in the DP.

Range-AP Assignment (Segment Overwrite) — P2 Easy

Problem in one paragraph: Array A of length N; Q queries each assign A[l+i] = x + i*y for i = 0..r-l (an arithmetic progression written into a range, overwriting anything previously there); after all queries, output the sum of A mod 1e9+7. Reconstruction note: this problem's constraints use corrupted exponent glyphs (10!, 10"); read as the standard 10^5 for N/q and 10^9 for A[i] bounds, consistent with the sample sizes and the mod-1e9+7 requirement.

Pattern: offline reverse-order interval overwrite using a DSU "next unclaimed index" pointer — every index ends up with the value from the last query that touched it, so process queries newest→oldest and only fill indices nobody has claimed yet.

Key insight: A naive lazy-segment-tree "assign AP over range" also works, but the DSU trick is simpler: walk queries backward, and for each query use find() to jump straight to the next still-unclaimed index inside [l, r], assign it, then union it forward past itself so the next find() skips it. Each index is claimed exactly once, so total work is O((N+Q) α(N)).

Walkthrough: Sample 1 — A=[5,5,5,0,3], queries in order Q1..Q5. Reverse order: Q5 (3,4,8,9) claims indices 3,4 → A[3]=8, A[4]=17. Q4 (2,4,9,6) — index 4 already claimed, only index 2 free → A[2]=9. Q3 (2,3,8,0) — indices 2,3 already claimed, nothing free. Q2 (0,1,6,5) claims 0,1 → A[0]=6, A[1]=11. Q1 (0,2,1,2) — all of 0,1,2 already claimed, nothing free. Final A=[6,11,9,8,17], sum=51. Matches expected output.

Solution (Python, tested):

import sys

MOD = 10**9 + 7

def solve(n, A, queries):
    parent = list(range(n + 1))

    def find(x):
        while parent[x] != x:
            parent[x] = parent[parent[x]]
            x = parent[x]
        return x

    claimed_value = [None] * n
    for (l, r, x, y) in reversed(queries):
        p = find(l)
        while p <= r:
            claimed_value[p] = (x + (p - l) * y) % MOD
            parent[p] = p + 1
            p = find(p + 1)

    total = 0
    for i in range(n):
        total += claimed_value[i] if claimed_value[i] is not None else A[i]
    return total % MOD

def main():
    data = sys.stdin.read().split()
    idx = 0
    n = int(data[idx]); idx += 1
    A = [int(data[idx + i]) for i in range(n)]; idx += n
    q = int(data[idx]); idx += 1
    queries = []
    for _ in range(q):
        l, r, x, y = (int(data[idx + i]) for i in range(4))
        idx += 4
        queries.append((l, r, x, y))
    print(solve(n, A, queries))

if __name__ == "__main__":
    main()

Complexity: O((N+Q) α(N)) time, O(N) space. Trap: process queries in reverse order — a forward pass with a naive DSU skip-pointer would let later queries incorrectly "skip" cells that earlier queries hadn't actually locked in yet; also remember the AP offset i is relative to that specific query's l, not the array's global index.

Verified: Sample1 → 51 ✓, Sample2 → 37 ✓, Sample3 → 16 ✓ (all three sample cases matched exactly).

1. Range AP-assign + range sum — EASY

Problem in one paragraph: Array A of n integers, q queries. Type-1 (1,l,r) overwrites A[i] for i in [l,r] with (i-l+1)*A[l] — i.e. it stamps an arithmetic progression starting at the original A[l] with common difference A[l] over the range, using the value A[l] had at the moment the query runs (so queries can chain/overwrite each other). Type-2 (2,l,r) asks for the sum over [l,r]. Output the sum of all type-2 answers mod 1e9+7. No statement ambiguity beyond that "replace" must be read as happening left-to-right in query order (query 2 in sample 1 re-stamps a sub-range already stamped by query 1, and the later stamp wins).

Pattern: Segment tree with lazy propagation, where the lazy tag is "assign this whole range to an AP with first term a and common difference d" (not a single value).

Key insight: A plain range-assign segment tree only supports one constant per range; here the assigned shape is a linear function of position, so the lazy tag must carry (a, d) and the push-down must recompute each child's a by offsetting with d * (child_start - range_start). Range-sum under a pushed AP tag is a closed-form arithmetic series sum, so both push-down and the sum query stay O(log n) per node touched, giving O((n+q) log n) overall.

2. Maximum-sum subarray with ≤ k distinct elements — EASY

Problem in one paragraph: Given array A (values can be negative) and integer k, find the maximum sum of a contiguous subarray that contains at most k distinct values, where the empty subarray (sum 0) is always a valid candidate.

Pattern: Two-pointer sliding window (distinct-count constraint) combined with a monotonic deque for sliding-window-minimum-of-prefix-sum.

Key insight: For a fixed right end r, the set of valid left ends is a contiguous, monotonically-non-decreasing-with-r range [lo(r), r] (shrinking the window from the left never increases distinct count). The best sum of a subarray ending at r within that range is prefix[r] - min(prefix[lo(r)-1 .. r-1]), and since both ends of that min-window move only rightward as r grows, a monotonic deque tracks the running minimum in amortized O(1) per step.

Walkthrough: Sample 1, N=11, k=2, A=[1,2,2,3,2,3,5,1,2,1,1]. As r sweeps right, lo(r) tracks to keep ≤2 distinct values in window; the best window found is indices 2..6 (1-indexed) = [2,2,3,2,3], sum 12. Sample 2: A=[-1,-2,-3], k=1 — every non-empty subarray has negative sum, so empty subarray (0) wins. Sample 3: A=[-1,1,3,2,-1], k=5 (k≥N so no distinct constraint) — best is [1,3,2]=6, dropping the leading and trailing −1s.

Solution (Python, tested):

import sys
from collections import deque, defaultdict

def main():
    data = sys.stdin.read().split()
    idx = 0
    n = int(data[idx]); idx += 1
    k = int(data[idx]); idx += 1
    A = [int(data[idx + i]) for i in range(n)]; idx += n

    prefix = [0] * (n + 1)
    for i in range(n):
        prefix[i + 1] = prefix[i] + A[i]

    freq = defaultdict(int)
    distinct = 0
    l = 0
    dq = deque()

    def dq_push(pidx):
        while dq and prefix[dq[-1]] >= prefix[pidx]:
            dq.pop()
        dq.append(pidx)

    dq_push(0)
    best = 0
    for r in range(1, n + 1):
        v = A[r - 1]
        freq[v] += 1
        if freq[v] == 1:
            distinct += 1
        while distinct > k:
            lv = A[l]
            freq[lv] -= 1
            if freq[lv] == 0:
                distinct -= 1
            l += 1
        while dq and dq[0] < l:
            dq.popleft()
        cur = prefix[r] - prefix[dq[0]]
        if cur > best:
            best = cur
        dq_push(r)

    print(best)

if __name__ == "__main__":
    main()

Complexity: O(n) time (amortized, two pointers + deque), O(n) space.

Trap: Negative values mean the "longest valid window" is not necessarily the best window — must take the max-suffix-sum inside the valid window (via the min-prefix trick), not just sum the whole window.

3. Minimum initial oil to minimize disturbances — EASY

Problem in one paragraph: N people process sequentially; A[i]=1 sells a litre (fails/"disturbs" if tank is at capacity C), A[i]=-1 buys a litre (fails/"disturbs" if tank is empty). Choose the minimum initial oil X (before anyone acts) that achieves the fewest possible disturbances.

Pattern: Prefix-sum / "minimum starting value to avoid going negative" (Kadane-adjacent classic).

Key insight: Underflow disturbances (can't buy from an empty tank) are avoidable by raising X; overflow disturbances (can't sell into a full tank) are capacity-bound and X can't fix them (case 3 proves this — X=0 still lets a disturbance happen because the tank literally hits capacity C regardless of start). The minimum X that eliminates every avoidable underflow is the classic X = max(0, -min_prefix_sum), where min_prefix_sum is the minimum prefix sum of A (including the empty prefix 0); this doesn't need to know C at all because raising X only ever prevents underflow, never trades against overflow (overflow is checked against C independently and capping doesn't change the walk's future trajectory since a rejected transaction just doesn't happen).

4. Minimum moves to reduce army to 1 — EASY

Pattern: Recursive memoized "integer replacement" (extended to two divisors) — the classic trick for Leetcode-397-style problems, generalized to divide-by-3.

6. Maximum "expert number" partition — MEDIUM

Problem in one paragraph: N employees on floors 1..N with skill A[i] (constraints say 1<=A[i]<=1000 but samples use 0 — read A[i] as 0..1000). Partition the array into contiguous teams; each team's value is its mex (smallest skill value ≥0 absent from the team). Maximize the sum of team mex values over all partitions.

Pattern: DP over partition points, dp[i] = max over j<i of dp[j] + mex(A[j..i-1]), accelerated using the fact mex is bounded by maxA + 1 and is monotonic non-decreasing as the window grows leftward.

Key insight: As the segment start j moves left from i-1, mex(j..i-1) is non-decreasing and saturates once all values 0..maxA have appeared (at most maxA+2 distinct extensions matter). Track it incrementally with a seen array while scanning left; once mex saturates, the mex term stops changing, so the rest of the range's contribution collapses to max(dp[j']) for j' in the remaining prefix — which is answered instantly via a running prefix-max array pmax, so the "expensive" walk per i is capped at O(maxA) and the tail is O(1).

Walkthrough: Sample 1: A=[0,2,1,1]. Best partition [0,2,1],[1]: mex([0,2,1])=3 (0,1,2 present, 3 missing... wait 1 present, 2 present, 0 present → mex=3), mex([1])=0 (0 absent). Total 3+0=3, matching output.

Solution (Python, tested):

import sys

def main():
    data = sys.stdin.read().split()
    idx = 0
    n = int(data[idx]); idx += 1
    A = [int(data[idx + i]) for i in range(n)]; idx += n

    maxv = 1001
    dp = [0] * (n + 1)
    pmax = [0] * (n + 1)
    seen = [False] * (maxv + 2)
    for i in range(1, n + 1):
        touched = []
        mex = 0
        best = -1
        j = i - 1
        while j >= 0:
            v = A[j]
            if v <= maxv + 1 and not seen[v]:
                seen[v] = True
                touched.append(v)
                while mex <= maxv + 1 and seen[mex]:
                    mex += 1
            cand = dp[j] + mex
            if cand > best:
                best = cand
            if mex > maxv:
                j -= 1
                break
            j -= 1
        if j >= 0:
            tail = pmax[j] + mex
            if tail > best:
                best = tail
        for v in touched:
            seen[v] = False
        dp[i] = best
        pmax[i] = max(pmax[i - 1], dp[i])
    print(dp[n])

if __name__ == "__main__":
    main()

Complexity: O(n · maxA) time (~1e5 × ~1e3 ≈ 1e8 worst case — tight in Python; in C++/PyPy comfortable, in CPython budget extra time or consider PyPy submission if the judge allows it), O(n) space.

Trap: The "expensive" per-i scan must stop the moment mex saturates and hand off to the prefix-max array — without that cutoff this degrades to true O(n²) and will TLE on the full 1e5 constraint even though it's correct on all samples.

Verified: sample 1 ✓ (3), sample 2 ✓ (5), sample 3 ✓ (10)

7. Covered ranges over dynamic connected components — MEDIUM

Problem in one paragraph: n nodes, initially no edges; beauty(s) of a node-value-set is the number of maximal runs of consecutive integers needed to cover it. Process q queries: type 1 adds an edge (merging two components); type 2 asks for the covered-range count of the component containing a given node. Output the sum of all type-2 answers mod 1e9+7.

Pattern: Weighted-union DSU (small-to-large merging) where each component additionally tracks a Python set of its node values and a running count of "adjacent pairs" (x, x+1 both present) — covered-range count = component size − adjacent-pair count.

Key insight: beauty(s) = |s| − (number of x in s with x+1 also in s), because each such adjacency merges two would-be separate runs into one. When merging two components via small-to-large, only the elements of the smaller set need to be checked against the larger set's membership for new adjacencies crossing the merge boundary — this keeps total work O(n log n) since every element is moved into a bigger set at most O(log n) times.

Walkthrough: Sample 3: n=10, edge (1,4) merges components {1} and {4} into {1,4}; no x has x+1 also present (1+1=2 not in set, 4+1=5 not in set) → adjacency 0 → covered ranges = 2 − 0 = 2. Query on node 1 and node 4 both resolve to this same component, giving 2 + 2 = 4, matching output.

Solution (Python, tested):

import sys

def main():
    data = sys.stdin.buffer.read().split()
    idx = 0
    n = int(data[idx]); idx += 1
    q = int(data[idx]); idx += 1
    t = int(data[idx]); idx += 1

    parent = list(range(n + 1))
    node_set = [None] * (n + 1)
    adj_count = [0] * (n + 1)
    size = [1] * (n + 1)
    for v in range(1, n + 1):
        node_set[v] = {v}

    def find(x):
        while parent[x] != x:
            parent[x] = parent[parent[x]]
            x = parent[x]
        return x

    def union(a, b):
        ra, rb = find(a), find(b)
        if ra == rb:
            return
        if size[ra] < size[rb]:
            ra, rb = rb, ra
        big_set = node_set[ra]
        small_set = node_set[rb]
        adj = adj_count[ra] + adj_count[rb]
        for x in small_set:
            if (x - 1) in big_set:
                adj += 1
            if (x + 1) in big_set:
                adj += 1
        big_set.update(small_set)
        adj_count[ra] = adj
        size[ra] += size[rb]
        parent[rb] = ra
        node_set[rb] = None

    total = 0
    for _ in range(q):
        row = data[idx:idx + t]; idx += t
        typ = int(row[0])
        if typ == 1:
            union(int(row[1]), int(row[2]))
        else:
            r = find(int(row[1]))
            total += size[r] - adj_count[r]

    print(total % (10**9 + 7))

if __name__ == "__main__":
    main()

Complexity: O((n+q) α(n) + n log n) amortized time (small-to-large merging), O(n) space.

Trap: Must check adjacency in both directions (x−1 and x+1) for every element crossing the merge boundary — checking only one direction undercounts adjacent pairs and inflates the covered-range answer.

Verified: sample 1 ✓ (1), sample 2 ✓ (2), sample 3 ✓ (4)

8. Minimum jumps around a circular jump-chair game — MEDIUM

Problem in one paragraph: N chairs in a circle, chair i lets you jump exactly A[i] chairs left or right (wrapping around). Starting at chair X, find the minimum number of jumps to reach chair Y, or -1 if unreachable.

Pattern: BFS on an implicit graph where each node has exactly 2 outgoing edges (jump distance is fixed per-node, direction is the only choice).

Key insight: Because each chair has a fixed jump length (only direction is free), the state space is just the N chairs themselves (no extra dimension needed), so plain BFS from X with the two candidate neighbors (pos - 1 ± A[pos]) mod N + 1 (1-indexed, mod-wrapped) finds the shortest path in O(N) total.

Walkthrough: Case 1: N=5, X=5, Y=1, A=[1,2,3,2,4] (1-indexed). From chair 5, A[5]=4: right → (5-1+4)%5+1 = 3+1... compute: (4+4)%5+1 = 8%5+1=3+1=4; left → (4-4)%5+1=0+1=1 = Y. Reached in 1 jump. Matches output 1.

import sys
from collections import deque

def main():
    data = sys.stdin.read().split()
    idx = 0
    n = int(data[idx]); idx += 1
    x = int(data[idx]); idx += 1
    y = int(data[idx]); idx += 1
    A = [0] + [int(data[idx + i]) for i in range(n)]

    if x == y:
        print(0)
        return

    dist = [-1] * (n + 1)
    dist[x] = 0
    dq = deque([x])
    while dq:
        cur = dq.popleft()
        step = A[cur]
        for nxt in ((cur - 1 + step) % n + 1, (cur - 1 - step) % n + 1):
            if dist[nxt] == -1:
                dist[nxt] = dist[cur] + 1
                if nxt == y:
                    print(dist[nxt])
                    return
                dq.append(nxt)

    print(dist[y])

if __name__ == "__main__":
    main()

Trap: Both jump directions can land on the same chair (e.g. when the jump length is a multiple related to N), so dedupe/guard against re-adding an already-visited chair — a naive BFS without the dist == -1 check before enqueue can double-enqueue and waste time but won't break correctness; the real trap is the 1-indexed circular wraparound arithmetic ((cur - 1 ± step) % n + 1), easy to get off-by-one.

Minimum k for path length >= m in "adjacent-if-smaller" graph — P1 HARD #11

Problem in one paragraph. Given permutation p of length n, edge i->j exists iff p[i]<p[j] and |i-j|<=k. Find minimum k such that the graph's longest path has >= m nodes.

Recognition signals: - "minimum k such that some monotonic property holds" -> answer is monotonic in k -> binary search on k. - "longest path" on a DAG defined by index-window + value-increasing -> this is LIS with a window constraint, not general longest-path (the graph is a DAG since edges only go from smaller value to larger value along any orientation — still need care, but it's DAG-like via topological order of values). - n <= 1e5 rules out any O(n^2) longest-path recomputation per binary-search step; needs an O(n log n) check.

Attack or skip? Skip on sight. Even though "binary search + windowed-LIS with a Fenwick/segment tree keyed by value" is the right idea, implementing a correct O(n log n) longest-path-under-window check from scratch under exam pressure is a 45+ minute build with multiple failure points (segment tree over values needs range updates as the window slides). Not a 60-85 min problem for a non-competitive candidate.

Approach in 5 steps max: 1. Binary search on k in [0, n-1]; property "longest path >= m" is monotonic in k (larger k only adds edges). 2. For a fixed k, compute longest increasing chain where step i->j is allowed only if |i-j|<=k and p[i]<p[j]. 3. Process indices left to right; maintain a Fenwick/segment tree indexed by value p[i], storing best chain length ending at that value, but only considering indices within the last k window (need a second structure, e.g. sorted by index, to expire old entries — or offline sliding-window max over value ranges). 4. Query max chain length for values < p[i] among indices in [i-k, i-1], update at p[i]. 5. Check if the max computed value >= m; adjust binary search bounds.

Complexity target: O(n log n log n) — binary search (log n) x each check (n log n).

Recognition signals: - "value product is a perfect square" -> factor out square part: reduce each a[i] to its squarefree kernel (divide out every prime to an even power); two numbers multiply to a perfect square iff they have the SAME squarefree kernel. - "sum of beauty over all subtrees" -> classic small-to-large merging or Euler-tour + Fenwick-by-DFS-order counting technique (each pair (i,j) contributes to every ancestor of LCA(i,j), so precompute per-pair contribution = depth(LCA)+1, or equivalently accumulate via DSU-on-tree/small-to-large with a hashmap counting kernel frequency). - N <= 1e5, values <= 1e9 -> squarefree-kernel factorization needs trial division up to sqrt(1e9) ~ 31623, feasible with precomputed small primes / Pollard's rho if needed, but likely trial division suffices given typical test data.

Longest non-decreasing subsequence with XOR >= M, N<=1000 — P3 3.1 HARD (label) — VERIFIED SOLVABLE

Problem in one paragraph. Array A of length N<=1000, integer M<=500, A[i]<=N. Find the length of the longest non-decreasing subsequence whose XOR of elements is >= M.

Recognition signals: - N <= 1000 (not 1e5!) with A[i] <= N (small value range) -> screams O(N^2) or O(N^2 x small-constant) DP is intended despite the "HARD" label; this is a giveaway that competitive-tier tricks are NOT required. - "non-decreasing subsequence" + "track XOR" -> DP indexed by (position, xor-value-so-far), since XOR values are bounded by the next power of two above N (<=1023 for N<=1000) — small enough to be a DP dimension. - This is the standout "attack" pick among all 8 — small N is the tell.

Attack or skip? ATTACK. This is the one problem on this list a strong-but-not-competitive candidate should genuinely solve in the room. Approach in 5 steps max: 1. For each index i, maintain dp[i] = dict mapping {xor_value -> max subsequence length ending at i with that xor_value}, initialized dp[i][A[i]] = 1. 2. (If TLE is a real worry, cap can be tightened by deduplicating dominated states, but for N=1000 plain dict DP is the pragmatic exam choice.)

Trap: Don't confuse "non-decreasing subsequence" with the more familiar strictly-increasing LIS — equal values are allowed to chain (verified in sample 2, where [1,1] is a valid subsequence but its XOR=0 fails the M=1 bound, giving answer 1 not 2).

Verified Python (tested against all 3 official samples — all pass):

def get_ans(N, M, A):
    dp = [None] * N
    best = 0
    for i in range(N):
        cur = {A[i]: 1}
        for j in range(i):
            if A[j] <= A[i]:
                for x, l in dp[j].items():
                    nx = x ^ A[i]
                    cand = l + 1
                    if cur.get(nx, 0) < cand:
                        cur[nx] = cand
        dp[i] = cur
        for x, l in cur.items():
            if x >= M and l > best:
                best = l
    return best
