Creating a grid

R, C = 3, 4

grid = [[0] * C for _ in range(R)]     # ✅ THE ONLY correct way
grid = [[0] * C] * R                   # ☠️ BROKEN — see Traps tab

# from known values
grid = [[1,4,3],
        [2,5,4],
        [7,5,9]]

# dimensions — memorise this shape
R = len(grid)          # number of ROWS
C = len(grid[0])       # number of COLUMNS (length of first row)

grid[row][col] — row first, always. Not (x, y). The most common indexing bug is silently swapping them.

Reading a grid from input

# Typical OA input:
#   3 3
#   1 4 3
#   2 5 4
#   7 5 9

R, C = map(int, input().split())
grid = []
for _ in range(R):
    grid.append(list(map(int, input().split())))

# one-liner version
grid = [list(map(int, input().split())) for _ in range(R)]

Type this without thinking. In a 15-minute problem, fumbling input parsing costs a third of your budget.

Iterating

# every cell, row by row
for i in range(R):
    for j in range(C):
        print(grid[i][j], end=' ')
    print()

# when you only need values, not positions
for row in grid:
    for val in row:
        ...

# a whole row     -> grid[i]
# a whole column  -> [grid[i][j] for i in range(R)]
# row sums        -> [sum(row) for row in grid]
# column sums     -> [sum(grid[i][j] for i in range(R)) for j in range(C)]
# total sum       -> sum(sum(row) for row in grid)
# print nicely    -> for row in grid: print(*row)

Coordinates — build the mental picture once

j=0 j=1 j=2
i=0 [0,0] [0,1] [0,2]
i=1 [1,0] [1,1] [1,2]
i=2 [2,0] [2,1] [2,2]
  • i grows downward (rows), j grows rightward (columns)
  • Move down = i+1 · up = i-1 · right = j+1 · left = j-1
  • Top-left = grid[0][0] · bottom-right = grid[R-1][C-1] (or grid[-1][-1])
  • In bounds ⟺ 0 <= i < R and 0 <= j < C — write this check as a helper, every time

💀 The five traps

1. [[0]*C]*R — the silent killer costs whole problems

bad = [[0]*3]*3
bad[0][0] = 99
print(bad)   # [[99,0,0], [99,0,0], [99,0,0]]   ← ALL THREE ROWS CHANGED

good = [[0]*3 for _ in range(3)]
good[0][0] = 99
print(good)  # [[99,0,0], [0,0,0], [0,0,0]]     ← correct

*R copies the reference to one row R times, so every "row" is the same list. Your DP table looks right, produces garbage, and gives no error. Always use the list-comprehension form.

2. Swapping i and j

grid[j][i] instead of grid[i][j]. On a square grid it silently transposes your answer; on a rectangular grid it throws IndexError. Say "row, column" out loud as you type the brackets.

3. Using R where C belongs

for i in range(R):        # rows   → uses R
    for j in range(C):    # cols   → uses C

Swap them on a non-square grid and you get IndexError; on a square grid it works by luck and breaks on the hidden test case.

4. Forgetting the bounds check before moving

# ALWAYS guard before stepping to a neighbour
if 0 <= ni < R and 0 <= nj < C:
    ...

Python's negative indexing makes this worse than in C: grid[-1] doesn't error, it silently wraps to the last row. Off-grid moves become wrong answers instead of crashes.

5. Mutating the input grid when you needed a copy

copy = [row[:] for row in grid]     # ✅ real copy of every row
copy = grid[:]                      # ☠️ shallow — rows still shared
import copy as cp; cp.deepcopy(grid)  # works, slower

📐 Four templates that cover almost every OA matrix problem

Learn these four shapes and you can attempt essentially any grid question you'll meet at this tier.

1 · Grid DP this was Staples P2

def min_path_sum(grid):
    R, C = len(grid), len(grid[0])
    dp = [[0]*C for _ in range(R)]

    for i in range(R):
        for j in range(C):
            if i == 0 and j == 0:
                dp[i][j] = grid[i][j]              # start
            elif i == 0:
                dp[i][j] = dp[i][j-1] + grid[i][j]  # top row: only from left
            elif j == 0:
                dp[i][j] = dp[i-1][j] + grid[i][j]  # left col: only from above
            else:
                dp[i][j] = grid[i][j] + min(dp[i-1][j], dp[i][j-1])
    return dp[-1][-1]

The four-case shape (start / top row / left column / general) is the whole template. Handle the edges first and the general case writes itself. Swap min→max for max-path, drop grid[i][j] and use + for counting paths.

2 · Grid DFS — flood fill / islands

def num_islands(grid):
    if not grid: return 0
    R, C = len(grid), len(grid[0])
    seen = set()

    def dfs(i, j):
        if i < 0 or i >= R or j < 0 or j >= C: return   # bounds
        if (i,j) in seen or grid[i][j] != 1: return     # visited or water
        seen.add((i,j))
        dfs(i+1,j); dfs(i-1,j); dfs(i,j+1); dfs(i,j-1)  # 4 directions

    count = 0
    for i in range(R):
        for j in range(C):
            if grid[i][j] == 1 and (i,j) not in seen:
                dfs(i,j); count += 1
    return count

3 · Grid BFS — shortest path in an unweighted grid

from collections import deque

def shortest(grid, start, goal):
    R, C = len(grid), len(grid[0])
    q = deque([(start[0], start[1], 0)])     # (i, j, distance)
    seen = {start}
    DIRS = [(1,0), (-1,0), (0,1), (0,-1)]    # keep this constant handy

    while q:
        i, j, d = q.popleft()
        if (i,j) == goal: return d
        for di, dj in DIRS:
            ni, nj = i+di, j+dj
            if 0 <= ni < R and 0 <= nj < C and (ni,nj) not in seen and grid[ni][nj] != 1:
                seen.add((ni,nj))
                q.append((ni, nj, d+1))
    return -1

BFS (queue) gives the shortest path in an unweighted grid; DFS does not. Weighted edges → Dijkstra with a heap.

4 · Transform in place — transpose / rotate

# transpose (swap across the main diagonal)
for i in range(R):
    for j in range(i+1, C):          # note: j starts at i+1, not 0
        grid[i][j], grid[j][i] = grid[j][i], grid[i][j]

# rotate 90° clockwise = transpose, then reverse each row
for row in grid:
    row.reverse()

# quick non-in-place transpose
list(zip(*grid))                     # tuples
[list(r) for r in zip(*grid)]        # lists

If j starts at 0 instead of i+1, you swap every pair twice and get the original grid back — a classic "my code does nothing" bug.

D6 · PATTERN Staples P2
Minimum path sum from top-left to bottom-right, moving only right or down.
[[1,4,3],[2,5,4],[7,5,9]] → 21 
def min_path_sum(grid):
    R, C = len(grid), len(grid[0])
    dp = [[0]*C for _ in range(R)]
    for i in range(R):
        for j in range(C):
            if i == 0 and j == 0: dp[i][j] = grid[i][j]
            elif i == 0:          dp[i][j] = dp[i][j-1] + grid[i][j]
            elif j == 0:          dp[i][j] = dp[i-1][j] + grid[i][j]
            else:                 dp[i][j] = grid[i][j] + min(dp[i-1][j], dp[i][j-1])
    return dp[-1][-1]

This is the exact problem you couldn't touch in the Staples OA. Type it until it's automatic.

D7 · PATTERN
Unique paths: how many distinct right/down routes from top-left to bottom-right of an R×C grid? 
def unique_paths(R, C):
    dp = [[1]*C for _ in range(R)]     # first row & col are all 1
    for i in range(1, R):
        for j in range(1, C):
            dp[i][j] = dp[i-1][j] + dp[i][j-1]
    return dp[-1][-1]
# unique_paths(3,3) == 6

Same skeleton as D6 with + instead of min, and 1s instead of grid values. That substitution IS the pattern family.

D9 · PATTERN
Spiral order traversal — return all elements in spiral order.
[[1,2,3],[4,5,6],[7,8,9]] → [1,2,3,6,9,8,7,4,5] 
def spiral(grid):
    if not grid: return []
    out = []
    top, bot = 0, len(grid)-1
    left, right = 0, len(grid[0])-1
    while top <= bot and left <= right:
        for j in range(left, right+1): out.append(grid[top][j])
        top += 1
        for i in range(top, bot+1): out.append(grid[i][right])
        right -= 1
        if top <= bot:                                  # guard needed
            for j in range(right, left-1, -1): out.append(grid[bot][j])
            bot -= 1
        if left <= right:                               # guard needed
            for i in range(bot, top-1, -1): out.append(grid[i][left])
            left += 1
    return out

Four boundaries that close inward. The two if guards matter — without them, single-row or single-column leftovers get emitted twice.

D10 · PATTERN
Shortest path in a binary grid (0 = open, 1 = wall), from (0,0) to (R-1,C-1), 4-directional. Return step count or −1. 
from collections import deque

def shortest_path(grid):
    R, C = len(grid), len(grid[0])
    if grid[0][0] == 1 or grid[R-1][C-1] == 1: return -1
    q = deque([(0, 0, 0)])
    seen = {(0,0)}
    for_dirs = [(1,0), (-1,0), (0,1), (0,-1)]
    while q:
        i, j, d = q.popleft()
        if i == R-1 and j == C-1: return d
        for di, dj in for_dirs:
            ni, nj = i+di, j+dj
            if 0 <= ni < R and 0 <= nj < C and (ni,nj) not in seen and grid[ni][nj] == 0:
                seen.add((ni,nj))
                q.append((ni, nj, d+1))
    return -1

Mark cells as seen when you enqueue, not when you dequeue — otherwise the same cell enters the queue many times and BFS degenerates.
